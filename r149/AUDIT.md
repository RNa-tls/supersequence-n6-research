# 라운드 149 — `H.models` 최종 독립 감사 요약

정본 라운드-148 상태 `583f0b6` 에서 분기한 브랜치
`round149-opus-hmodels-audit` 에서 수행.  상세 증명은 `r149/PROOF.md`.

## 감사가 바꾼 것

라운드 148 에서 `H.models` 는 `L6 = 872` 경로에 남은 **단 하나의
`PURE_HAND_PROOF` 노드**였고, 그 내용은 "세 상한 모형의 정의와 각각이 무엇을
완화하는지에 대한 손 논증" 이라는 한 줄이었다.  이 감사는 그것을 여섯 개의
증명 의무로 쪼개고, 그중 **다섯 개를 유한 열거로 닫았다**.

| 의무 | 내용 | 라운드 148 | 라운드 149 |
|---|---|---|---|
| (O1) | 추출이 사슬족을 만든다 | 손 | 손 (§3, 변환 성격 분류) |
| (O2) | 모든 걸음이 카탈로그 이동 | **묵시적** | **전수 증명** (518,400 쌍, 누락 0) |
| (O3) | 요금 규칙이 항등식/정의 | **묵시적** | **전수 증명** (720/720, 3600/3600) |
| (O4) | 자원 총합이 예산 안 | 손 | 손, 단 Claim 3 과 Lemma F 를 새로 증명 |
| (O5) | 탐색기가 최댓값을 계산 | 기계 | 기계 (+ 독립 인증서 검사기) |
| (O6) | 시작 포트 고정 WLOG | 손 | **전수 확인** (동변성 위반 0, 추이적) |
| (D) | `t <= 4` 에서 성립 | **경험적** | **구조적 증명** (정리 5.1-5.3) |

## 이 감사가 실제로 찾아낸 것

1. **묵시적 수학 가정 네 개.**  C 카탈로그의 `continue`, heavy 목록의 두
   제외(`t == v`, `t == end(v)`), 탐색기 인덱스 상한이 `t <= 4` 를 덮는지,
   clean-E 의 궤도 유지 검사가 제약인지 항등식인지 — 전부 코드 동작이
   수학적 주장으로 기능하고 있었다.  넷 다 형식화했다 (`PROOF.md` §9).
2. **내 감사 스크립트 자신의 버그.**  더미를 품은 `beta` 성분을 순환으로 보고
   회전시켜 존재하지 않는 무게-6 간선 `342156 -> 123456` 을 만들어 heavy
   예산을 터뜨렸다.  더미는 쓰기 순서의 시작·끝이므로 그 성분은 이미 경로다.
3. **`t <= 4` 예산이 탐색기 한계 안임을 아무도 적어 두지 않았다.**  전수 계산
   결과 최대 `b=4, d=20, a=20, bb=3, e=3, h=4` 로 한계 `(5,40,24,24,24,6)`
   미만이다.  묵시적 클램프도 범위 거부도 일어날 수 없다.
