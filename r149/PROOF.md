# `H.models` 감사 — 독립 수학적 증명

라운드 148 이 `L6 = 872` 경로에 남긴 유일한 `PURE_HAND_PROOF` 의존성이
`H.models` 다.  이 문서는 그것을 구현에서 분리해 처음부터 다시 세우고, 특히
**가설적 `t <= 4` 영역**에서 성립함을 구조적으로 증명한다.  실제 덮개에서
관찰된 사실은 **증거로도 쓰지 않는다** — 아래 증명 어디에도 "반례를 못 봤다"
는 단계가 없다.

---

## 0. `H.models` 가 실제로 주장하는 것

라운드 148 보고서의 도식 `sum_P <= cap(b,d,a,bb,e,h)` 는 **신뢰하지 않는다**.
저장소에서 복원한 정확한 주장은 다음이다.

> **주장 (H.models).**  길이 `L = 867 + t` 인 임의의 `n = 6` 덮개 `W` 에 대해,
> `W` 의 고정 대표원에서 라운드-142 추출이 만드는 사슬족 `{X_i}` 는
> (i) 각 `X_i` 가 아래 §2 의 **전이 체계** 안의 워크이고,
> (ii) 그 워크들의 자원 총합이 `W` 의 좌표행이 주는 **예산** 안에 있으며,
> (iii) 따라서
> `sum_i P(X_i) <= max { sum_i cap(K_i) : K_i 가 그 예산의 분할 }`
> 이다.  여기서 `cap(K)` 는 예산 벡터 `K` 를 갖는 워크의 **최대 포트 수**다.

핵심은 이것이 **닫힌 형태의 부등식이 아니라는 점**이다.  `cap` 은 유한한
전이 체계 위의 최댓값이고 그 값은 전수 탐색이 준다.  그러므로 손으로 증명해야
하는 것은 숫자가 아니라 **모형화의 충실성**이다:

    (O1) 추출이 잘 정의되고 사슬족을 만든다
    (O2) 각 사슬의 모든 걸음이 전이 체계의 이동이다      <- 카탈로그 완전성
    (O3) 각 걸음이 전이 체계의 요금 규칙을 어기지 않는다  <- 규칙 = 항등식/정의
    (O4) 자원 총합이 행의 예산 안이다                    <- 추출 Claim 1-5
    (O5) 탐색기가 정확히 그 워크들의 최댓값을 계산한다
    (O6) 시작 포트를 하나로 고정해도 일반성을 잃지 않는다 <- 좌 S6

`(O2)`, `(O3)`, `(O6)` 은 **유한 열거로 완결**되며 아래에서 그렇게 증명한다.
`(O4)` 는 손 논증이고 `(O1)` 과 함께 §3 에서 감사한다.  `(O5)` 는 기계이며
두 독립 구현이 905/905 셀에서 일치한다.

## 1. 대상의 정확한 정의

`n = 6`, `N = 720`.  덮개 `W` 의 **선택 창**은 `W` 안에서 처음 나타나는 720 개
순열 창이다.  연속한 선택 창의 시작 위치 차이를 **간격**이라 하고, 간격 1 인
최대 연속열을 **pass** 라 한다.  pass 수를 `P`, `G := P - 120` 이라 둔다.

* `sigma(s) = s[1:] + s[0]` (회전).  `sigma`-류를 **육각형** (120 개).
* `tau(s) = s[1:-1] + s[0] + s[-1]`.  `tau`-류를 **궤도** (144 개, 각 5 원소).
  `tau^5 = id` 이므로 각 궤도는 정확히 5 개의 **위상**을 갖는다.
* pass `i` 의 진입 순열을 `v_i`, 길이를 `l_i`.
* `end(v) := sigma^{-1}(v) = v[5] + v[:5]`.
* **조인트**: pass 끝에서 다음 pass 진입까지의 간격 `w >= 2`.  `w` 를 **무게**.
* `O` = 선택 창이 만나는 궤도 수, `k := O - 24`.
* `S` = 무게 `>= 3` 조인트 수, `Hh := sum (w-3)_+`.
* `nu(i)` = 진입이 `sigma^{l_i}(v_i)` 인 pass.  `alpha = nu` + 더미,
  `T` = 쓰기 순서 후속, `beta = T o alpha^{-1}`.  `K := c(beta)`.
* `c` = **순수 순환** 수 (모든 간선이 clean-E 인 `beta`-순환).

### 보조정리 1.1 (`G <= 5k`)

`P` 개의 pass 는 `O` 개 궤도 안에 있고 각 궤도는 위상이 5 개뿐이므로
`P <= 5 O = 5(24 + k) = 120 + 5k`, 즉 `G <= 5k`. ∎

`t` 에 전혀 의존하지 않는 계수 논증이다.

### 보조정리 1.2 (순수 순환은 궤도 전체)

clean-E 간선은 `tau` 다 (§2.1 (C1)).  그러므로 순수 순환은
`v -> tau v -> tau^2 v -> ...` 이고 `tau^5 = id` 이므로 정확히 5 개의 pass 를
가지며 한 궤도를 **전부** 덮는다. ∎

## 2. 전이 체계와 그 완전성 (O2, O3, O6)

### 2.1 이동 카탈로그

포트 `v` 에서 나가는 조인트의 **출발 창은 `end(v) = sigma^{-1}(v)`** 이고,
목표는 다음 pass 의 진입 `t` 다.  `g := ` `end(v)` 에서 `t` 로의 최대 겹침
거리.  `spell := end(v) + t[6-g:]` 의 내부 창 중 순열인 것들을 `hid` 라 하자.

    g = 1   -> t = v: pass 내부의 걸음이지 조인트가 아니다
    g = 2, hid = []            -> clean E
    g = 2, hid = [v]           -> 타입 A (dirty)
    g = 3, hid = [v, *], hex 같음 -> 타입 B (dirty)
    g = 3, 그 밖                  -> 유료 5 종 (120 / 201 / 210 / E_SIGMA / SIGMA_E)
    g >= 4                        -> heavy, 비용 w - 3

### 정리 2.2 (카탈로그 완전성) — **전수 증명됨**

720 x 720 = 518,400 개 순서쌍을 전부 열거했다
(`r149/src/catalogue_complete149.py`, `r149/certs/catalogue_complete_149.json`):

| 간격 | 쌍 수 | 분류됨 | **누락** |
|---|---:|---:|---:|
| 1 | 720 | (pass 내부, 조인트 아님) | — |
| 2 | 1,440 | 1,440 | **0** |
| 3 | 4,320 | 4,320 | **0** |
| 4 | 17,280 | heavy (비용 1) | **0** |
| 5 | 86,400 | heavy (비용 2) | **0** |
| 6 | 408,240 | heavy (비용 3) | **0** |

무게 `>= 7` 은 불가능하다: 두 6-창의 겹침은 0..5 이므로 `w <= 6`.

heavy 목록이 빼는 쌍은 `t = v` 와 `t = end(v)` 뿐 (각 720 개).  둘 다 실제
조인트로 **불가능**하다: `t` 는 **첫 출현**인데 `v` 와 `end(v)` 는 조인트를
취하는 시점에 **이미 쓰인 창**이다. ∎

> 즉 탐색기가 취할 수 없는 실제 조인트는 **존재하지 않는다**.  이것이 `(O2)`
> 이고, 완전 열거로 닫혔다.

### 정리 2.3 (요금 규칙은 항등식이거나 정의) — **전수 증명됨**

| 규칙 | 내용 | 근거 |
|---|---|---|
| (C1) | clean-E 간선 `= tau` | 720/720 확인 |
| (C2) | 타입 A `= sigma`, 타입 B `= sigma^2` | 720/720 확인 |
| (C3) | A, B 의 목표는 출발과 **같은 육각형** | 720/720 확인 |
| (C4) | 유료 간선은 **절대** 출발 육각형에 착지하지 않는다 | 3,600/3,600 확인 |
| (C5) | 위상 재사용 금지 `<=>` 포트(=첫 출현)가 서로 다름 | 정의 |
| (C6) | 이미 연 궤도로 들어가는 non-clean-E 걸음 = 토큰 1 | 추출 Claim 3 의 `tok_i` 정의 |
| (C7) | 새 궤도 `+4`, 재진입 `-1` `<=>` `D = 5O - P` | §4.1 |

(C1) 에서 clean-E 는 궤도를 **떠날 수 없다**.  그러므로 탐색기의
`if (free E && orbit != current) return;` 은 제약이 아니라 **항등식의 재확인**
이다 (제약이었다면 과도한 제약이 되어 건전성을 깰 수 있었다).

(C3) + (C4) 로 **이미 쓴 육각형에 착지할 수 있는 걸음은 A, B, 그리고 보통
충돌(유료·heavy 가 다른 육각형과 부딪히는 경우)뿐**이고, 앞의 둘은 `a`, `bb`
에서, 나머지는 `e` 에서 값을 치른다.  누락된 경우가 없다.

### 정리 2.4 (시작 포트 고정은 WLOG) — **전수 확인됨**

좌 `S6` (알파벳 재라벨링) 은 `sigma`, `tau`, 겹침 거리, 내부 창의 순열 여부를
모두 보존하므로 카탈로그 전체와 가환이다.  12,360 개 (군원, 포트) 표본에서
`free`, `dirtyA`, `dirtyB`, `paid` 5 종, `heavy` 711 종 전부 **위반 0**.
좌 `S6` 는 720 개 순열 위에 **추이적**이므로 시작 포트를 `123456` 으로
고정해도 일반성을 잃지 않는다. ∎

## 3. 추출 정리 (A) 와 자원 장부 (O1, O4)

`W` (고정 대표원) 에서:

1. pass 를 만든다 — **동치 변환** (덮개 ↔ 선택 창 열).
2. `beta` 성분으로 분해 — **분할** (각 pass 는 정확히 한 성분).
3. 순수 순환 `c` 개를 **삭제** — 보조정리 1.2 로 궤도 전체 5 포트씩.
4. 남은 `K - c = d + 1` 개 성분(순환)을 non-E 간선 하나에서 **개방** — 간선
   삭제, 포트는 보존.
5. heavy 조인트 `h` 개를 **절단** — 간선 삭제, 포트 보존.  clean-E 간선은
   절대 자르지 않는다.

결과는 `d + 1 + h` 개의 **경로 = 사슬**이고, 모든 clean-E 블록은 정확히 하나의
사슬 안에 있다.  heavy 를 자르지 않으면 `d + 1` 개.

각 변환의 성격: 1 동치, 2 분할, 3 삭제(정확), 4·5 간선 삭제.
**어떤 변환도 포트를 만들거나 복제하지 않는다.**  간선 삭제는 워크를 더 짧게
만들 뿐 포트를 늘릴 수 없으므로 **완화(relaxation)** 방향이다.

### Claim 1 — `sum_i P_i = P - 5c = 120 + G - 5c`
순수 순환은 궤도 전체 5 포트(보조정리 1.2), 나머지 pass 는 정확히 한 사슬에
속한다 (2 는 분할, 4·5 는 간선만 지운다). ∎

### Claim 2 — `sum_i D_i = 5k - G + 5*sigma`
`D_i := 5 O_i - P_i`, `sigma := sum_i O_i - (O - c)`.
`sum_i D_i = 5 sum_i O_i - sum_i P_i = 5(O - c + sigma) - (120 + G - 5c)
           = 5O + 5 sigma - 120 - G = 5k - G + 5 sigma` (`O = 24 + k`). ∎

### Claim 3 — `sum_i tok_i = B* - sigma`
사슬 안에서 clean-E 간선만이 궤도와 블록을 동시에 유지한다.  같은 궤도의
최대 연속열 수는 `runs_i = O_i + e_i` (`e_i` = 이미 연 궤도로 들어가는 궤도
간 간선 수), 블록 수는 `blocks_i = runs_i + x_i` (`x_i` = 궤도 내 non-E 간선).
`tok_i := e_i + x_i` 이므로 `blocks_i = O_i + tok_i`.  합해
`blocks = (O - c + sigma) + sum tok_i`, `B* := blocks - (O - c)` 로
`sum tok_i = B* - sigma`. ∎

### Claim 4 — `sigma >= 0`, 사슬 하나면 `sigma = 0`
사슬들의 궤도 집합의 합집합이 순수 순환 밖 `O - c` 개 궤도이므로
`sum O_i >= O - c`. ∎

### Claim 5 — 사슬 내부 육각 반복 `<= R_int`, A/B 가 각각 하나씩
유지된 A 또는 B 간선의 목표는 (C3) 으로 출발과 같은 육각형이고 출발은 바로
앞 포트이므로, 그 목표는 사슬 내부 육각 반복 하나를 차지한다.  전체 내부
반복 수가 `R_int` 이하라는 것은 **SAME-HEX 정리** (`H.samehex`,
`src/l6_same_hex_145.py`) 이며 `D2 + Qs <= R_int <= 2g` 를 준다. ∎

### 행이 주는 예산 (Claim 1-5 의 직접 귀결)

    사슬 수        = d + 1 + h   (분할 모형) 또는 d + 1 (병합 모형)
    sum 결손       = 5k - G + 5s
    sum 토큰       = B* - s
    sum a <= D2,   sum bb <= Qs,   sum e <= max(0, Z - Qs)
    sum (a+bb+e) <= R_int <= 2g
    필요 포트      = 120 + G - 5c

`sum e <= Z - Qs` 의 유도: `a + bb + e <= R_int <= 2g` 이고 `2g = D2 + Z - d`
(행 정의 `z = G - c = 2g + d`, `D2 = z - Z`) 이므로
`e <= 2g - D2 - Qs = Z - d - Qs <= Z - Qs`. ∎

## 4. 포트 소유권 / 청구 증명 (C)

사슬 `X = (v_1, ..., v_P)` 의 각 포트 `v_j` (`j >= 2`) 에 **정확히 하나씩**
자원을 배정한다.  자원은 두 축으로 나뉘고 두 축은 서로 독립이다.

### 4.1 궤도-위상 축

| `v_j` 의 상황 | 소유 자원 |
|---|---|
| 새 궤도를 연다 | 그 궤도 (열림) |
| 이미 연 궤도, 걸음이 clean-E | 그 궤도의 남은 위상 하나 |
| 이미 연 궤도, 걸음이 clean-E 아님 | 토큰 1 |

clean-E 는 (C1) 로 `tau` 이므로 **현재 궤도 안에서만** 움직인다.  따라서
"이미 연 **다른** 궤도"로 들어가는 모든 걸음은 clean-E 가 아니고 토큰을 정확히
하나 쓴다.  **단사성**: 한 걸음은 위 세 경우 중 정확히 하나에 속한다.

**결손 항등식.**  궤도를 열 때 `+4`, 재진입할 때 `-1`, 첫 포트가 `+4` 로
시작하므로 끝에서
`D = 4 O - (P - O) = 5 O - P`.  이것은 각 궤도의 **미사용 위상 수의 합**과
같다.  탐색기의 증분 규칙 (C7) 이 이 항등식 그 자체다.

**중복 계산 없음**: 위상은 궤도마다 5 개뿐이고 각 포트는 정확히 하나의
`(궤도, 위상)` 쌍이다 (순열 하나 = 쌍 하나).  같은 쌍을 두 포트가 가질 수
없다 (C5).

### 4.2 육각형 축

| `v_j` 의 상황 | 소유 자원 |
|---|---|
| 새 육각형에 착지 | 그 육각형 (120 개) |
| 이미 쓴 육각형, 걸음이 타입 A | `a` 한 단위 |
| 이미 쓴 육각형, 걸음이 타입 B | `bb` 한 단위 |
| 이미 쓴 육각형, 그 밖 | `e` 한 단위 |

(C3) 로 A, B 의 목표는 **반드시** 출발 육각형이고, (C4) 로 유료 간선은
**절대** 출발 육각형에 착지하지 않는다.  그러므로 네 경우는 서로 배타적이고
모든 경우를 덮는다.  따라서

    P <= 120 + a + bb + e                                   ... (P2)

이것이 탐색기의 표 없는 prune `reach2` 이며 **증명된 상한**이다.

### 4.3 두 축의 상호작용과 공유

* 한 포트는 궤도 축에서 자원 하나, 육각형 축에서 자원 하나를 쓴다.  **두 축을
  더하지 않으므로** 중복 계산이 아니다.  각 축이 독립적으로 상한을 준다.
* `a`, `bb`, `e` 는 `a <= D2`, `bb <= Qs`, `e <= Z - Qs` 와
  `a + bb + e <= 2g` 를 **동시에** 만족해야 한다.  이는 같은 자원을 두 번 세는
  것이 아니라 **제약의 논리곱**이다 (한 단위가 `a` 한도와 공유 한도 양쪽을
  동시에 소비한다).
* **사슬끼리의 공유는 없다**: 사슬은 pass 를 분할하므로 포트를 공유하지 않고,
  예산은 행 수준 총합을 사슬에 나눈 것이며 모형은 그 **모든 분할에 대한
  최댓값**을 취한다 (`r148/src/rows148.py::best`).
* 끝점 공유 없음: 개방과 절단은 간선만 지우므로 경로들은 정점 서로소다.
* 반복 창은 pass 가 아니므로 `P` 에 **들어가지 않는다** — 반복은 조인트의
  내부 창으로만 나타나고, 그것이 A/B/heavy 를 구분하는 기준이다.

### 4.4 왜 닫힌 형태 상한이 아닌가 (정직한 서술)

4.1 과 4.2 가 주는 닫힌 부등식은 `P = 5O - D` 와 `P <= 120 + a + bb + e` 다.
이 둘만으로는 실제 용량보다 훨씬 약하다 (예: `C(0,0) = 20` 인데 (P2) 는 120).
**진짜 제약은 기하학적**이다 — 어떤 궤도 다음에 어떤 궤도가 올 수 있는지,
그리고 그때 육각형이 새것인지가 카탈로그로 결정된다.  그 유한한 전이 체계
위의 최댓값이 `cap` 이고, 그것은 전수 탐색이 계산한다.

따라서 **손으로 증명할 것은 숫자가 아니라 §2 와 §3** 이고, 이 문서가 닫은
것이 정확히 그 부분이다.  숫자 부분은 기계이며 두 독립 구현이 905/905 에서
일치하고 (`r147/certs/second_impl_147.json`), 도달 가능성 절반은 독립
인증서 검사기가 따로 확인한다 (`r149/src/certcheck149.py`).

## 5. `t <= 4` (D) — 최우선 증명 의무

### 정리 5.1 (`t` 는 모형에 나타나지 않는다)

§2 의 카탈로그, §2.3 의 요금 규칙, §4 의 소유권 배정, 그리고 Claim 1-5 의
증명 어디에도 `t` 가 나오지 않는다.  `t` 가 들어오는 자리는 **행 열거뿐**이다:

    t = k + Z + Hh + B*,      0 <= G <= 5k  (보조정리 1.1)

그러므로 모형의 타당성은 `t` 에 대해 **균일**하다.  `t = 5, 6` 에서의 관찰을
`t <= 4` 로 외삽하는 단계가 **없다**. ∎

### 정리 5.2 (`t <= 4` 행은 탐색기의 선언 범위 안)

숨은 위험은 하나뿐이다: `t <= 4` 인 행이 탐색기가 처리할 수 없는 예산을
요구하면, 구현이 조용히 잘라내거나 거부해 **묵시적 수학 가정**이 된다.
모든 `t <= 4` 행 (1 + 14 + 85 + 353 + 1156 = 1,609 개, `s` 포함) 의 예산
최대치를 전수 계산했다:

| 예산 | `t <= 4` 최대 | 탐색기 한계 | 여유 |
|---|---:|---:|---|
| 토큰 `b` | 4 | `UBT = 5` | ✔ |
| 결손 `d` | 20 | `UBD = 40` | ✔ |
| `a` | 20 | `UBA = 24` | ✔ |
| `bb` | 3 | `UBA = 24` | ✔ |
| `e` | 3 | `UBA = 24` | ✔ |
| `h` | 4 | `UBH = 6` | ✔ |

모두 **한계 미만**이므로 클램프도 범위 거부도 발생할 수 없다.  (`b <= B* <= t`,
`d = 5k - G + 5s <= 5t + 5t = 40` 이 `t <= 4` 에서 성립하는 것도 보조정리
1.1 과 `s <= B*` 에서 바로 나온다.) ∎

### 정리 5.3 (`t <= 4` 에서만 나타나는 구조는 없다)

전이 체계는 `t` 와 무관하므로 (5.1), `t <= 4` 인 가설적 덮개의 사슬도 §2 의
같은 워크 집합에 속한다.  예산이 작을수록 워크 집합은 **작아질 뿐** 커지지
않는다 (모든 예산이 "이하" 형태, `research/RR_L6_R147_SOUND_UB.md` (P1)).
그러므로 `t <= 4` 에서 모형을 넘는 구조가 나타나려면 §2 의 워크가 아니어야
하는데, 정리 2.2 로 그런 조인트는 존재하지 않는다. ∎

## 6. 반례 탐색 (E)

**추상 모형 반례는 정의상 불가능하다.**  `cap(K)` 는 예산 `K` 의 워크 전체에
대한 최댓값이므로 "모형을 넘는 워크"란 모순이다.  의미 있는 반례는 오직

    실현 가능한 덮개에서 나오지만 전이 체계 밖인 사슬

뿐이고, 정리 2.2 (누락 0) 와 정리 2.3 (규칙이 항등식) 이 그것을 배제한다.

그럼에도 다음을 실제로 시도했다 (`r149/src/walk_check149.py`):

* 실제 덮개 40 개의 사슬을 **걸음마다** 전이 체계로 재생 — 위반 0.
* 그 과정에서 이 감사 스크립트 자신의 버그를 하나 잡았다: 더미를 품은 성분을
  순환으로 보고 회전시켜 존재하지 않는 무게-6 간선
  (`342156 -> 123456`) 을 만들어 heavy 예산을 터뜨렸다.  더미는 쓰기 순서의
  시작과 끝이므로 그 성분은 이미 경로다.  고친 뒤 위반 0.

최소 예산부터의 탐색: `(0,0,0,0,0,0)` 에서 `cap = 20` 이고 실제 872 표준족이
정확히 20 을 달성한다 (§8).  한 단위 예산, 두 자원 상호작용, 비대칭 예산은
모두 셀 표에 이미 들어 있고 단조성 위반 0 으로 확인되어 있다
(`r147/certs/monotonicity_147.json`, 1,101 셀).

## 7. 작은 `n` 반증 (F)

`n = 4, 5, 6` 에서 카탈로그 구조를 독립적으로 만들어 비교했다:

| `n` | 무게 2 | 무게 3 | 누락 | clean-E `= tau` | A `= sigma` | B `= sigma^2` | 유료가 출발 육각형에 착지 |
|---|---:|---:|---:|---|---|---|---:|
| 4 | 48 `= 2*4!` | 144 `= 6*4!` | 0 | ✔ | ✔ | ✔ | 0 |
| 5 | 240 `= 2*5!` | 720 `= 6*5!` | 0 | ✔ | ✔ | ✔ | 0 |
| 6 | 1,440 | 4,320 | 0 | ✔ | ✔ | ✔ | 0 |

즉 §2 가 쓰는 구조적 사실은 **`n = 6` 의 우연이 아니다**.  숨은 `n = 6` 특수
가정은 발견되지 않았다.

> 정직한 단서: `n = 4, 5` 의 무게-3 유료 분류(`120/201/210` 코드)는 `n = 6`
> 전용이라 이 탐침에서는 거칠게 대체했다.  그래서 이 표는 **소스당 개수**
> (`2*n!`, `6*n!`) 와 세 항등식의 일반성을 보이는 데까지만 쓰고, 그 이상을
> 주장하지 않는다.  작은 `n` 의 성공을 증명으로 쓰지 않는다.

## 8. 등호와 빡빡함 (G)

표준 872 족의 추출은 사슬 **하나**, `sum P = 20`, `O_1 = 4`, `sum D = 0`,
`sum tok = 0`, `a = bb = e = h = 0` 이다.  즉 예산 벡터 `(0,0,0,0,0,0)` 이고
`cap(0,0,0,0,0,0) = 20` 이므로 **여유 0 — 정확히 빡빡하다**.

구조적 이유: `D = 0` 이면 `P = 5O` 이므로 **연 궤도가 전부 완전히 채워진다**.
토큰 `0` 이면 이미 연 궤도로 **되돌아갈 수 없다**.  그러므로 사슬은
"한 궤도를 clean-E 로 5 포트 전부 훑고, 유료 간선으로 새 궤도로 나간다"의
반복이고, 유료 간선은 (C4) 로 새 육각형에 착지해야 한다 (`e = 0`).
그 사슬이 네 궤도까지만 이어질 수 있다는 것이 `cap = 20` 의 내용이다.

**`t <= 4` 가 더 강한 공유를 쓸 수 있는가?** 없다.  각 행에 대해 모형은 그
행의 예산을 갖는 **모든** 워크의 최댓값을 이미 취한다.  더 강한 공유 패턴이
있다면 그것도 그 최댓값 안에 들어 있다.  예산 밖으로 나가는 유일한 길은 §2 의
워크가 아닌 것인데, 정리 2.2 가 그것을 막는다.
