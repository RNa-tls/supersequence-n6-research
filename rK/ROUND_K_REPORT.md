**결론부터.** L₈ = 46187은 **증명하지 못했고**, 길이 ≤ 46186인 단어도 **찾지 못했다**. 이번 라운드에서 새로 엄밀하게 얻은 것은 다음 세 가지이다.

2. **모든 특수쌍에 걸친 A/B 번들 패킹의 최대 절약 = 42** (풀이기 없는 전수 열거).
   * 특수쌍을 섞어도 6A보다 나은 A/B/φ 분할은 없다.
3. **"클래스 덮개 LP" 계열 방법의 원리적 한계.**
   * 이번에 찾은 더 효율적인 닫힌 trail 때문에, 어떤 trail-분할 LP도 **46138**을 넘지 못한다(이전 장벽은 46143).
   * 윈도우형 trail 자동자는 β = 5/33에서 포화된다. 그 이유는 S4 음절이 국소적으로 10번까지 유효하기 때문이다.

## 1. ≤ 46186의 예산 (§1)

**r=0, 정확한 항등식**(rJ/rI, Lean `R0Identity`):

    L = 45364 + Σ_T (k_T + 1) + λ = CONST + E + (τ − 1) + λ = 46204 − Σ_T s_T + λ

여기서 `E = q − 720`, `λ = Σ_{trail 사이}(c − 4) ≥ 0`, `s_T = |T|/6 − (k_T + 1)`이다.

인증된 trail 비율 하한 `k_T + 1 ≥ (5/33)|T|`(§3)을 넣으면 다음 예산이 나온다(`certs/budget_r0_46186.json`).

| 양 | L ≤ 46186이려면 |
|---|---|
| E + (τ − 1) + λ | ≤ 101 |
| E + τ | ≥ 44 (따라서 r=0 하한 46128) |
| λ | ≤ 58 |
| Σ_T s_T | ≥ 18 + λ |
| s_T | ≤ \|T\|/66 (모든 trail) |
| φ보다 효율적인 trail에 든 클래스 | ≥ 1188 (전체의 23.6%) |
| 허용 (E+τ, λ, τ) 조합 | 112,100개 |

**일반 경로(r ≥ 0), 첫 원리에서**(`budget.py` 주석 참조):

    L = 45366 + R_extra + Σ_{c ≥ 2 전이}(c − 2)

여기서 `R_extra = Σ_C (p_C − 1)`이고, p_C는 클래스 C가 나뉜 조각 수이다. 따라서 L ≤ 46186 ⇔ `R_extra + Σ(c − 2) ≤ 820`이다.

* r>0에서 이 예산을 유한 경우로 줄이는 작업(§17–20)은 **하지 못했다**.

## 2. 고효율 trail 분류 상태 (§2–§4, §8)

**증명됨**(계산 검사, `macro_check.py`의 보조정리 R).

* 꽉 찬 chain 두 개는 BAC로만 이어진다.
* BAC로 이어진 꽉 찬 chain은 최대 6개이다.
* 따라서 모든 trail은 다음 두 매크로 문자의 열이다. F 다음에 F는 오지 않는다.
  * **N(l)**: 비완전 chain 하나, l ≤ 6
  * **F(j)**: 최대 BAC 연쇄, j ≤ 6

**β* (모든 r=0 trail의 최소 비용/클래스 비율)의 위치.**

* 하한: 5/33 = 0.151515… (인증, §3)
* 상한: **0.153530… = 187/1218**. 이번 라운드에 찾은 닫힌 trail (S3 S3 S4 S2 S4 S4 S4)⁶에서 나온다. 1218클래스, 186 chain, 절약 16이다.
  * 이전 상한은 (S2 S3 S3 S4 S4)⁶의 0.154501이었다.
  * `long_trail_search.py`: S4 위주 길이 ≤ 20 단어 517,614개를 검사했고, 기존보다 나은 trail 20여 종을 찾았다(`certs/long_trail_search_20_3.json`).
* 국소 최적 패턴: S4 = N(5) F(4), 비율 5/33.
  * S4는 10번 반복하면 닫히는 유효한 trail(330클래스)이다.
  * 그래서 매크로 윈도우를 약 20 문자까지 늘려도 하한은 5/33에서 움직이지 않는다.
* S5 = N(5) F(5)(국소 비율 3/20)는 반복하면 충돌한다. 이것이 Round I의 46120(=3/20)이 46128로 오른 이유이다.

**미완(정직한 기록).**

* "≤ 46186 경로에 나타날 수 있는 모든 trail"의 완전 분류는 얻지 못했다.
* 양의 절약 trail은 길고(평균 chain 길이 > 6) 수가 매우 많다. 전역 유일성 제약 때문에 유한 자동자로 정확히 닫을 수 없었다.

## 4. 열 생성 / 가격 문제 (§6–§7)

* **주 문제 LP**(클래스 정확 덮개, 열 = trail, 비용 k+1)는 S₈가 클래스에 추이적으로 작용한다.
  * 그래서 최적 쌍대는 균등 β*이고, LP 값은 45364 + 5040·β*이다.
  * 가격 문제 = "비율이 β보다 작은 trail 찾기" = β* 계산이다.
* 인증된 쌍대: 클래스당 5/33. 따라서 **LP 값 ∈ [46128, 46138]**이다(상한은 187/1218 trail에서 나온다).
* 분지-가격 정수 최적은 46187 이상이어야 한다(그 경우 L₈=46187의 r=0 부분이 증명된다). 그러나 근 간격이 **≥ 44단위**이다. 5040클래스에서 이를 닫는 분지는 시도하지 않았다(규모상 불가능하다고 판단).

## 12. 덮이지 않은 단 하나의 전역 경로 부류

> **"A/B/φ 언어 밖의 trail을 쓰는 r=0 경로"와 "모든 r>0 경로".**

r=0 쪽은 정확히 말하면 다음과 같다.

* Σ_T s_T − λ ≥ 18이어야 하고, 따라서 1188개 이상의 클래스를 φ보다 효율적인 trail로 덮어야 한다.
* 그런데 그 trail들의 클래스 집합이 단일 특수쌍 φ-집합들의 합집합(번들)이 아닌 경로들이다.
* 대표적인 후보는 S-음절 trail이다(비율 0.15353까지, φ보다 효율적).
* 그러나 이 trail들은 φ-집합을 하나도 포함하지 않는 "반-번들"이다. 그래서 이들을 쓰면 여집합을 φ-사이클로 덮을 수 없고, 다른 비-φ trail로 메워야 한다.
* 빠져 있는 정리는 다음과 같다. **반-번들 trail을 쓴 정확 분할의 (Σ(k+1) + λ) ≥ 822를 보이는 패킹 하한.** 클래스 덮개 LP는 이를 원리적으로 볼 수 없다(LP ≤ 46138, §4).
