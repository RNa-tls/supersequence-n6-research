# 라운드 152 — 용량 셀의 독립 검증 가능한 인증서

이 문서는 마지막으로 남아 있던 인증 공백, 곧 **적재 용량표
(load-bearing capacity table) 가 정말 맞는가** 를 닫기 위한 것이다.
라운드 147~151 까지의 상태에서 `cap(K)` 값은 결국 "생산 탐색기
`r147/src/l6_chain_capacity_147.c` 가 트리를 소진했다고 말했다" 에
의존하고 있었다.  아래에서는 그 의존을 없앤다.

---

## 1. `cap(K)` 의 수학적 정의

### 1.1 대상

`S6` 의 720 개 순열 문자열 위에서 다음을 정의한다 (모두 라운드 149
`r149/PROOF.md` 의 정의와 같다).

* `sigma(s) = s[1:] + s[0]`, 육각형 = `sigma` 궤도 (120 개).
* `tau(s) = s[1:5] + s[0] + s[5]`, 궤도 = `tau` 궤도 (144 개, 각 5 원소).
  궤도 안에서의 `tau` 지수를 **위상(phase)** 이라 부르고 `0..4` 로 쓴다.
* `end(v) = v[5] + v[:5]`.
* `gap(e, t) = min { k in 1..5 : t 가 e[k:] 로 시작 } `, 없으면 `6`.

`v` 에서 나가는 **결합(joint)** 은 `gap(end(v), t)` 로 분류한다.

| 무게 | 종류 | 표기 | 값 |
|---|---|---|---|
| 2 | 숨은 창 없음 | clean-E | 0 (토큰도 0) |
| 2 | 숨은 창 = `v` | dirtyA | 예산 `a` 1 |
| 3 | 숨은 창 2 개, 첫째 `= v`, 같은 육각형 | dirtyB | 예산 `bb` 1 |
| 3 | 나머지 5 종 (120/201/210/E_SIGMA/SIGMA_E) | paid | 토큰 1 |
| >= 4 | heavy | heavy | 예산 `h` 를 `gap-3` 만큼 |

### 1.2 사슬 (chain)

**예산 벡터** `K = (b, d, a, bb, e, h)` 를 고정한다.
`K` 에 대한 **사슬**은 순열 열 `v_0, v_1, ..., v_{m-1}` 로서

1. `v_0 = 123456`.  (정리 2.4 — 좌 `S6` 가 추이적이고 카탈로그가 동변이므로
   시작 포트 고정은 WLOG 다.  `r149/PROOF.md` §2.4, 518,400 쌍 전수 확인.)
2. 각 `i` 에 대해 `(v_i, v_{i+1})` 은 위 표의 결합이다.
3. **위상 상이성**: 한 궤도 안에서 같은 위상을 두 번 쓰지 않는다.
4. **clean-E 는 궤도를 떠나지 않는다**: clean-E 걸음의 도착 궤도는 출발 시점의
   현재 궤도와 같아야 한다.
5. **토큰**: 걸음이 clean-E 도 아니고 새 궤도를 여는 것도 아니면 토큰 1 을
   쓴다.  총 토큰 <= `b`.
6. **예산**: dirtyA 총 <= `a`, dirtyB 총 <= `bb`, heavy 비용 총 <= `h`,
   그리고 **보통 육각형 충돌** (dirtyA/dirtyB 가 아닌 걸음이 이미 방문한
   육각형에 착지하는 경우) 총 <= `e`.
7. **적자**: `deficit = 5 * (열린 궤도 수) - m` 이 `<= d`.

`cap(K)` 는 그런 사슬의 최대 `m` (= 포트 수) 이다.

조건 5~7 이 전부 "이하" 이므로 **(P1) 단조성** — `K <= K'` (성분별) 이면
`cap(K) <= cap(K')` — 은 정의에서 바로 나온다.  또 한 걸음마다 새 육각형을
쓰거나 `a + bb + e` 중 한 단위를 쓰므로 **(P2)** `cap(K) <= 120 + a + bb + e`.
두 명제의 증명은 `research/RR_L6_R147_SOUND_UB.md` 에 있다.

접두사도 사슬이므로, "어떤 시점에 적자가 `<= d` 이고 포트가 `m` 인 사슬" 의
최대값과 위 정의는 같다.  생산 탐색기가 `best[deficit]` 을 매 노드에서
갱신하는 것은 이 동치를 쓰는 것이다.

## 2. 인증서 형식 `L6-CAPCERT-2`

평문이다.  첫 줄이 매직 `L6-CAPCERT-2`, `#` 이후는 주석,
그 뒤로 셀마다 두 덩어리:

```
cell <b> <d> <a> <bb> <e> <h> <cap> <nports>
<nports 개의 포트 번호>
```

포트 번호는 `"123456"` 의 720 개 순열을 **사전순**으로 나열했을 때의 순위다.
검사기들이 그 목록을 각자 만들기 때문에 인증서 파일에는 어떤 표도 들어 있지
않다.  셀은 **파일에 적힌 순서대로** 검사되며, 그 순서가 곧 인증 순서다.

## 3. 인증서가 증명하는 것

셀 `K` 와 주장 `cap(K) = C` 에 대해 검사기는 **두 방향을 모두 스스로**
확립한다.

* **하한 `cap(K) >= C`** — 저장된 증인을 한 걸음씩 재생한다.  각 걸음이
  카탈로그의 결합인지, 위상이 겹치지 않는지, clean-E 가 궤도를 떠나지
  않는지, 여섯 예산이 모두 지켜지는지, 마지막으로 항등식
  `deficit = 5 * (궤도 수) - (포트 수)` 가 성립하는지를 확인한다.
  포트 수가 `C` 와 다르면 `WITNESS_BAD`.
* **상한 `cap(K) <= C`** — `C + 1` 개의 포트를 갖는 사슬을 **소진 탐색**으로
  직접 찾는다.  찾으면 `DISAGREE` (주장이 반증됨), 노드 상한에 걸리면
  `UNKNOWN_CAP`, 아무것도 못 찾고 끝나면 상한이 확립된다.

둘 다 성공한 셀만 `EXACT_CERTIFIED` 다.

### 3.1 순환이 없는 이유

소진 탐색에는 가지치기가 필요하다.  검사기가 쓰는 가지치기는 두 가지뿐이다.

1. `(P2)` 의 해석적 값 `120 + a + bb + e` — 증명된 명제이므로 입력이 아니다.
2. `(P1)` 단조 상계 — 남은 예산 벡터를 지배하는 셀의 용량.  **단, 같은
   실행에서 이미 `EXACT_CERTIFIED` 가 된 셀만** 쓴다.  생산 UB 테이블은
   읽지 않는다.

따라서 셀 `K` 의 상한은 오직 (i) 증명된 해석적 명제와 (ii) 이 실행이 이미
스스로 증명한 값들에만 의존한다.  인증 순서가 곧 귀납 순서다.

### 3.2 생산자는 신뢰되지 않는다

`r152/src/producer152.py` 는 증인만 제시한다.  소진 탐색은 하지 않으며,
가지치기에 생산 테이블을 heuristic 으로 써도 무방하다.  생산자가 값을
낮게 적으면 검사기가 `DISAGREE`, 높게 적으면 증인이 모자라서
`WITNESS_BAD` 가 된다.  어느 쪽도 숨길 수 없다.

### 3.3 실패는 닫힌 방향으로

노드 상한 도달은 **절대로** 합격이 아니다 (`UNKNOWN_CAP`).
한 셀이라도 `EXACT_CERTIFIED` 가 아니면 검사기는 0 이 아닌 종료 코드를 낸다.

## 4. 두 개의 독립 검사기

| | `r152/src/checker152.py` | `r152/src/checker152.c` |
|---|---|---|
| 언어 | Python | C |
| 카탈로그 | 문자열 대수에서 재구축 | 문자열 대수에서 재구축 |
| 생산 코드 import | 없음 | 없음 |
| 생산 UB 테이블 | 읽지 않음 | 읽지 않음 |
| 읽는 것 | 인증서 평문 | **같은** 인증서 평문 |

두 검사기는 서로의 코드를 쓰지 않는다.  같은 바이트를 읽고 각자 결론을
낸다.  노드 수까지 일치하면 두 탐색 트리가 같다는 뜻이고, 그것은 우연이
아니라 정의가 하나뿐이라는 뜻이다.
