# 라운드 146 — 적대적 검증 보고서

전제: 라운드 145 증명은 **독립적으로 무혐의가 밝혀질 때까지 유죄**.  목표는
증명을 예쁘게 만드는 것이 아니라 **깨뜨리는 것**.

결론부터: **깨졌다.**  `L6 >= 872` 와 `L6 = 872` 는 철회한다.  현재 확정 구간은
`L6 ∈ {870, 871, 872}`.  전말은 `research/ERRATA_146_CHAIN_UB.md`.

상태 라벨은 엄격히 쓴다: PROVED / REFUTED / EXHAUSTIVELY_VERIFIED /
TESTED_ONLY / UNKNOWN_CAP / UNAVAILABLE.  TESTED_ONLY 를 PROVED 로 승격하지
않고, UNKNOWN_CAP 을 불가능으로 승격하지 않는다.

## 1. §9 등호행 논거 — **EXHAUSTIVELY_VERIFIED (단, 매달릴 곳이 없어짐)**

세 등호 증인 (Q1 #0, Q1 #1, Q2 #0) 에 대해 "강제된 순수 순환이 존재하는가" 를
**세 번째 독립 판정기** 로 다시 물었다 (`src/l6_cover_bfs_146.py`): 상태는 `F`
위의 정수 비트마스크, 탐색은 재귀 DFS 가 아닌 층별 BFS, 낭비 장부는 제거했다
(`|F| = 4c` 에서 낭비가 `c` 로 강제됨을 증명).  육각/궤도 분할은 `sig`/`tau`
문자열 대수로 재구성한 뒤 생산 테이블과 교차 검증했다 (일치).

| 증인 | 포트 | `\|F\|` | `c` | `c` 개로 덮기 | 노드 | 실제 최소 궤도 수 | 여유 |
|---|---:|---:|---:|---|---:|---:|---:|
| Q1 #0 | 96 | 24 | 6 | **불가능** | 123 | 8 | 2 |
| Q1 #1 | 96 | 24 | 6 | **불가능** | 248 | 8 | 2 |
| Q2 #0 | 92 | 28 | 7 | **불가능** | 180 | 8 | 1 |

cap 없음.  마지막 두 열이 **양성 대조** 다: 같은 코드 경로가 같은 표로 `c = 8`
에서는 YES 라고 답한다.  즉 이 판정기는 YES 라고 말할 수 있는 상태에서 NO 를
말했다.

Q1 #0 의 손 계산도 독립 재현했다: `|hex(orbit) ∩ F|` 의 상위 여섯 값이
`5,5,3,3,3,3 = 22 < 24`.  **Q1 #1(26) 과 Q2 #0(35) 은 이 계수 논거만으로는
닫히지 않는다** — 문서가 Q1 #0 만 손으로 즉시 닫힌다고 쓴 것은 정확하다.

**그러나** §9 는 §8 이 남긴 두 행만을 다룬다.  아래 3 에서 §8 이 무너지므로
§9 는 혼자서 아무것도 닫지 못한다.

## 2. 고정 대표원 (B1) — **EXHAUSTIVELY_VERIFIED (n=3), TESTED_ONLY (n>=4)**

`|Φ(W)| = |W| ⟹ W = Φ(W)` 의 강직성을 `n = 3` 에서 **길이 13 까지 전수**
검사했다: 단어 2,391,471 개, 덮개 9,732 개, 길이가 같은 경우 54 개 전부 강직,
반례 0 (`src/l6_rigidity_146.py`, (R1)–(R4) 를 분리해 각각 따로 검사).
`n = 4, 5, 6` 은 표본 검사뿐이므로 **TESTED_ONLY** 로 남긴다.  반복 횟수 상한
`|W| − (n! + n − 1)` 은 손 증명이다.

## 3. §8 좌표행 소거 — **REFUTED**

이것이 이 라운드의 결정적 발견이다.

`src/l6_chain_capacity_144.c` 의 가지치기 표는 남은 예산의 **합** 으로 조회된다
(`left = (AMAX-au)+(BMAX-bu)+(EMAX-eu)`), 따라서 `UB[b][d][S][h]` 는 합이 `S`
이하인 **모든 분할에 대한 최댓값** 이어야 한다.  그런데
`l6_chain_rows_144.write_ub` 는 **분할마다 한 줄** 을 같은 키로 내보내고, C
로더는 같은 키의 **최솟값** 을 취한다.  425 개 키 중 **163 개** 에서 분할별
값이 다르다 (`b=0, d=0, S=10` 은 20~50).  표는 50 이 필요한 자리에 20 을
넘겨주었고, 탐색기는 과도하게 가지를 쳤고, 기록된 용량은 **참값보다 작다**.

측정 (둘 다 cap 없음):

```
./outputs/l6chain_144.exe 0 0 0 0  9 0 0 - 0  ->  50   (기록 45)
./outputs/l6chain_144.exe 0 0 0 0 10 0 0 - 0  ->  55   (기록 40)
```

`b = 0, d <= 1` 인 377 셀을 표 없이 전부 다시 계산한 결과 **87 셀** 이 기록값을
넘는다.  가장 큰 차이는 `0|1|1|0|13` 기록 50 → 참값 69.

가장 노골적인 흔적: `bound_below` 로만 기록된 6 개 셀은 `nodes = 1` 이다.  무효
표가 루트에서 바로 가지를 쳐, **한 노드만 보고** `CC <= 123` 을 주장했다.

용량은 상한으로 쓰이고 상한이 요구 포트 수보다 작을 때 행을 닫는다.  너무 작은
상한은 닫히지 않아야 할 행을 닫는다.  모형별 의존도:

| 길이 | 좌표행 | 사슬 상한이 **필요한** 행 |
|---|---:|---:|
| `L = 869` (`t=2`) | 85 | **0** |
| `L = 870` (`t=3`) | 353 | **61** |
| `L = 871` (`t=4`) | 1156 | **552** |

## 4. 조각(piece) 모형 — 결함과 무관, **EXHAUSTIVELY_VERIFIED**

조각 모형의 UB 파일은 마스크 `00` 셀만 내보낸다 (가장 느슨한 마스크이므로 같은
`(b,d)` 의 모든 마스크에 유효한 상한), 키에 예산 차원이 없고, 55 개 키 전부에
충돌하는 중복 줄이 **없다**.  표 자체도 건강하다: 마스크 지배(`00 >= 10 = 01 >= 11`)
위반 0, `(b,d)` 단조성 위반 0, capped 셀 0 (220 셀).  표본 5 셀
(`b=0, d=0/3/6/9`, `b=1, d=2`) 을 **가지치기 표 없이** 다시 계산해 네 마스크
값이 전부 정확히 일치했다.

그 결과 살아남는 것: `t = 0, 1, 2` 의 좌표행 `1 + 14 + 85 = 100` 개 **전부** 가
조각 모형 단독으로 닫힌다 (`outputs/rr_l6_piece_only_870_146.json`).
즉 **`L6 >= 870`**.

## 5. 복구 작업의 현재 상태 — **진행 중 (UNKNOWN)**

닫힘이 실제로 조회하는 **825 개 셀** 을 가지치기 표 없이 다시 계산하고 있다
(`src/l6_chain_recheck_146.py`).  표 없는 실행도 해석적 prune
`reach2 = ports + 미사용 육각형 + 남은 예산` 은 유지하므로 반환값은 그 셀의
정확한 용량이다.  475 셀을 마친 시점(나머지는 해석적 상한 `120 + a + bb + e` 로
대체 = 사실상 상한 없음)의 행 재평가 (`src/l6_rows_recheck_146.py`):

| 길이 | 좌표행 | 닫힘 | 열림 |
|---|---:|---:|---:|
| `L = 869` | 85 | **85** | 0 |
| `L = 870` | 353 | 331 | 22 |
| `L = 871` | 1156 | 900 | 254 (+2 flagged) |

재계산이 진행되면 열린 행 수는 **줄어들 수만 있다**.  그러나 표 없는 재계산의
비용은 기록 노드 수로 예측되지 않는다 — 과도한 가지치기가 심했던 셀일수록
기록 노드 수가 작고 실제 비용이 크다 (`0|14|0|0|0` 은 표 없이 9.0e8 노드,
133 초).  `d >= 14` 인 셀들이 남아 있어 **완주 여부는 미확정** 이다.

* **표 무결성 감사기가 잘못된 열 수의 UB 파일을 넘겼다.**  5 열 사슬 파일을

* **변이 시험 하네스가 추적되지 않는 파일을 `git checkout` 으로 되돌리려 했다.**
  주입한 결함이 남아 허위 발견을 만들었다.  내용 기반 snapshot/restore 로 고쳤고

* **공존 solver 양성 대조는 UNKNOWN_CAP.**  실제 872 덮개 위에서 모든 해를

## 15. `L6 = 872` 의 최종 상태

**성립하지 않는다 (증명되지 않았다).**

* `L6 <= 872` — 성립 (증인; 아카이브의 44,121 개 길이-872 덮개 전부 프레임워크 통과)
* `L6 >= 870` — 성립 (조각 모형 단독, `t <= 2` 의 100 개 행 전부)
* `L6 >= 871`, `L6 >= 872`, `L6 = 872` — **철회**

따라서 이 프로젝트가 지금 주장할 수 있는 것은 **`L6 ∈ {870, 871, 872}`** 이다.
라운드 145 의 마지막 문장("This project has not proved L6 >= 872." 에 반대되는
문장) 은 **철회** 하며, 정확한 현재 진술은 다음이다:

> **This project has not proved `L6 >= 872`.**
