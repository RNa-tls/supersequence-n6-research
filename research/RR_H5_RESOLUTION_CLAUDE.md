## 1. (H5) 의 정확한 서술 — 그리고 인증서가 필요로 하는 판본

라운드-107 인증서는 의무 그래프의 호를 **weight ≤ 3 joint 네 개**(`T1`–`T4`)로만 만들었다.
그 UNSAT 이 "완성이 없다" 를 뜻하려면 무엇이 참이어야 하는가.

| 판본 | 서술 |
|---|---|
| **A (H5-local)** | 이 상태들에서 미래의 모든 pass 는 weight ≤ 3 인 joint 를 쓴다 (무거운 joint 는 **합법적으로도** 일어날 수 없다) |
| **B (H5-target)** | 무거운 joint 가 합법일 수는 있으나, **목표를 만족하는 어떤 완성도** 그것을 포함하지 않는다 |
| **C (H5-replacement)** | 무거운 joint 를 쓰는 목표 완성마다 최소-weight 완성으로의 치환이 존재한다 |

> **인증서가 필요로 하는 것은 B 다.** DFS 는 `G_light`(비용 ≤ 1 호) 안에서만 분기하므로,
> 그 UNSAT 이 "완성 없음" 을 뜻하려면 *목표를 만족하는 완성의 의무 경로가 언제나 `G_light`
> 안에 있어야* 한다. A 는 B 를 함의하므로 A 로도 충분하고, C 도 충분하다.
> 세 판본은 서로 다르며 §7 에서 각각의 진위를 따로 판정한다.

## 2. `H` 를 정의부터 추적한다

**정의.** `H = Σ_{joint} max(ω − 3, 0)`. 엔진에서 직접:

```python
dS = int(move.weight >= 3)
dH = max(move.weight - 3, 0)
```

| 물음 | 답 | 근거 |
|---|---|---|
| 6,396 상태에서의 현재 값 | **전부 `H = 0`** | 아카이브 전수 (`Counter{0: 6396}`) |
| 허용되는 최종 값 | **`H ≤ 3`** — `H = 0` 이 아니다 | `final_target` 은 `Ndef + H ≤ TARGET_BUDGET = 3` 만 요구하고, `f1_prune_reason` 은 `H > 3` 에서만 자른다 |
| Area A 가 `H = 0` 으로 정의되는가 | **경계까지만 그렇다** | `search_rr_target_a_unified.q1_safe_prune_reason` 의 `H_positive` 는 `state.H > 0` 을 자르며, 그 근거는 **"Target A 의 인식기가 경계의 자식에 `H == 0` 을 요구한다"** 이다 |
| 처음/끝만인가 전 구간인가 | 경계까지는 **전 구간** (단조 + 경계에서 0). **경계 이후에는 제약이 없다** | 같은 곳 |
| `H` 는 단조인가 | **예** — `dH = max(ω−3,0) ≥ 0` | 리터럴 전이 **19,727**건에서 확인 |

> **결정적 사실.** `H = 0` 은 **Target A 경계에 도달하기까지**의 제약이다. Q2 가 묻는 것은
> 그 경계 상태에서 **완성**이 존재하는가이고, 완성의 목표(`final_target`)는 `H ≤ 3` 을
> 허용한다. 따라서 `H = 0` 슬랩 규약은 (H5) 를 주지 **않는다**.

## 3. 단순 `H`-단조성 경로 — **무효**

주장하려던 삼단논법:

```
H_현재 = 0 ,  H_최종 = 0 ,  ΔH >= 0  =>  ΔH = 0  =>  모든 미래 joint 의 weight <= 3
```

전제를 하나씩 검사하면:

* `H_현재 = 0` — **참** (6,396/6,396).
* `ΔH ≥ 0` — **참** (`dH = max(ω−3,0)`, 19,727건 확인).
* **`H_최종 = 0` — 거짓.** 목표는 `Ndef + H ≤ 3` 이고 `H` 단독으로는 3까지 허용된다.

> 세 번째 전제가 거짓이므로 **이 논증은 쓸 수 없다.** 라운드 107 이 (H5) 를 "슬랩 정의에서
> 한 줄로 따라 나올지 모른다" 고 적은 희망은 **실현되지 않는다.**

## 4. 목표 조건 경로 — 예산은 무거운 joint 를 금지하지 않는다

아카이브 상태는 전부 `F = 1`, `H = 0`, `Ndef = S + F − O = 0` 이므로

    B = 3 + K − Ndef − H = 3 + K = 3 + (25 − O),      O ∈ [3,10]  ⇒  B ∈ [18,25].

한편 weight-`w` joint 하나가 `S + H` 에 더하는 양은 `cost(ω) = [ω ≥ 3] + max(ω − 3, 0)`
(§5 에서 정확성 확인). `w = 4` 는 **2**, `w = 5` 는 3, `w = 6` 은 4.

미래 joint 는 `121 − P` = **107–108개**이고 예산은 21 안팎이다. 예를 들어 weight-4 joint
**10개**(비용 20)와 나머지 전부 무료인 완성은 예산 안에 있다. **따라서 예산 정리만으로는
무거운 joint 가 배제되지 않는다** — "무거운 joint 는 비싸다" 는 말로 (H5) 를 정당화할 수
없다는 라운드-107 의 지적이 옳다.

### 4.1 그러나 예산과 성분 하한을 **결합**하면 대부분이 배제된다

> **보조정리 (무거운-호 예산, 라운드 108).** `L2` 를 뿌리에서의 성분 개수 하한
> (`c − 1`, 무료 진입이 없으면 `c`) 이라 하고 `s := B − L2` 라 하자. 예산을 지키는 임의의
> 완성에서
>
>     Σ_{무거운 호} (cost − 1)  ≤  s .
>
> **증명.** 총비용 = (비-무료 호의 개수) + Σ_{비-무료}(cost − 1) 이고, 무료가 아닌 호의
> 개수는 보조정리 7(라운드 107, 임의의 비음 비용에 대해 성립)에 의해 `≥ L2` 이며, 무거운
> 호가 아닌 비-무료 호는 `cost − 1 = 0` 이다. 총비용 ≤ B 이므로 정리된다. ∎
>
> **따름정리.** `s = 0` 이면 무거운 joint 를 **하나도** 쓸 수 없다 — 그 인스턴스에서는
> **(H5) 가 정리다.** 또 일반적으로 `cost ≤ s + 1` 인 호만 쓸 수 있다.

이것이 계산을 가능하게 만든 열쇠다(§10).

미방문이기 때문이다. 모델이 쓰는 pass 는 `ℓ` 회전 **뒤**에 joint 를 놓으므로 `ΔF = 0` 이며,

**안전한 형태에 관한 주의.** 같은 (출발 단어, 목표 단어) 쌍을 서로 다른 weight 의 tail 이

## 8. 완전-joint 그래프 구성

정점 = 의무. 각 의무 `h` 에서 배정 단어 `A(h)` 를 `ℓ_h`(강제) 회전한 `y_h` 를 만들고,
**550개 tail 전부**를 적용해 목표 단어를 얻는다. 그것이 어떤 의무 `g ≠ h` 의 배정 단어면
호 `h → g` 를 넣고 비용 `cost(ω)` 를 붙인다. 같은 `(h,g)` 쌍은 **가장 싼 비용**만 남긴다
(§5 의 건전성 주의 참조). ROOT 호도 같은 규칙(`ℓ = 5`).

720 × 550 전개는 **한 번만** 해 `MC[y·720 + t]` 표(최소 비용, 없으면 255)로 저장한다 —
배정마다 다시 전개하지 않는다. 감사용으로 550개 tail 전부를
`outputs/rr_h5_audit/tail_generator.json` 에 내보냈다.

## 9. 비용-0 구조는 바뀌지 않는다 — 해석적 증명

> **정리 Z.** 전체 550개 tail 을 허용해도 비용-0 호는 `T1` 뿐이다.
>
> **증명.** `cost(ω) = [ω ≥ 3] + max(ω − 3, 0)` 이므로 `cost(ω) = 0 ⟺ ω ≤ 2`.
> `ω = 1` 인 이동은 회전이며 joint 가 아니다(pass 를 끝내지 않는다). `ω = 2` 인
> indecomposable tail 은 **정확히 하나**다 (weight 별 개수 `1, 1, 3, 13, 71, 461`), 그리고
> 그것이 `T1` 이다. ∎
>
> **따름정리.** `G₀` 와 `c(R)`, 그리고 라운드-107 보조정리 4 의 `outdeg_{G₀} ≤ 1` 은 완전
> 이동 집합에서도 그대로다. 완전-joint 탐색은 이 전제를 **모든 탐색 노드에서** `assert` 로
> 확인한다 — 위반 0.

**이것이 5,043개 강건 폐쇄가 살아남는 이유다** (§15).

## 10. 1,353 상태 완전-joint 재계산

`python3 src/certify_rr_full_joint.py --conditional` — **(H5) 를 어디에서도 쓰지 않는다.**

배정마다 다음 순서로 판정한다.

1. **가벼운 그래프만 싸게** 만들어 뿌리 하한 `L2` 와 여유 `s = B − L2` 를 잰다.
   (정리 Z 로 비용-0 호는 완전 이동 집합에서도 `T1` 뿐이므로 `s` 는 완전-joint 값과 같다.)
2. `s < 0` → **뿌리 하한만으로 폐쇄.** joint weight 와 무관하다.
3. `s = 0` → 무거운-호 예산 보조정리로 **무거운 호를 하나도 쓸 수 없다.** 가벼운 탐색이
   완전하므로 그것으로 판정한다. **이 인스턴스에서는 (H5) 가 정리다.**
4. `s ≥ 1` → 550개 tail 로 **완전-joint 그래프**를 만든다. 강제-호 하한(§10.1)이 무거운
   호를 전부 배제하면 다시 가벼운 탐색으로 끝내고, 아니면 완전-joint 정확 탐색을 돌린다.

### 10.1 강제-호 하한

> 경로가 호 `u → v` 를 쓰면 `u` 의 비용-0 후속 호와 `v` 로 들어오는 모든 비용-0 호는 쓸 수
> 없다 (각 정점은 후속도 선행도 하나뿐이다). 그것들을 지운 `G₀''` 의 약연결 성분 수를
> `c''` 라 하면 선형 숲 논증이 그대로 적용돼
>
>     총비용 >= (c'' − 1) + (cost(u→v) − 1) .
>
> 이 값이 `B` 를 넘으면 **어떤 완성도 그 호를 쓰지 못한다.** 모든 무거운 호가 이렇게
> 배제되면 그 인스턴스에서 (H5) 가 정리다.
>
> 함수형 그래프이므로 `c'' = m − (남은 호 수) + (남은 고리 수)` 로 **O(1)** 갱신된다.

결과는 §16 의 표에 있다.

## 13. `H = 0` 슬랩 경로 — **그런 정리는 없다**

  `state.H > 0` 을 자른다.
* `research/RR_PRUNE_TAXONOMY.md` 의 원장은 그 prune 을 **Q1-safe** 로 분류하고 근거를
  이렇게 적는다: *"Target A 의 인식기가 경계의 자식에 `H == 0` 을 요구한다"* + `H` 단조성.
* 즉 `H = 0` 은 **Target A 경계에 도달하기까지**의 제약이다. Q2 가 묻는 것은 **경계 이후의
  완성**이고, 그 목표(`final_target`)는 `Ndef + H ≤ 3` 만 요구한다.

> **결론: 문서화된 어떤 정리도 "genuine Q2/Area-A 완성이 `H = 0` 에 머문다" 고 말하지
> 않는다.** 라운드 107 이 기대한 한 문단짜리 따름정리는 **존재하지 않으며**, 우리는 그것을
> 발명하지 않는다.

## 14. 완전-joint 양성 대조

`ℓ = 5` 회전 뒤 커서에서 `exact.legal_moves` 가 내는 joint 전이 **5,870건**을 전부 `MC`
표와 대조했다 — **모델에서 빠진 전이 0건**. 최소-weight 대조도 유지한다(`T1` 이 weight-2

## 15. 정리 R — 5,043 상태는 joint weight 와 무관하게 배제된다

> **정리 R.** 라운드-107 인증서에서 **모든 cover 가 뿌리 성분 하한만으로 닫힌 5,043 상태**는,
> 완성이 어떤 joint weight 를 쓰든 목표를 만족하는 완성을 갖지 않는다.
>
> **증명.**
> 1. 정리 Z 로 비용-0 호는 전체 이동 집합에서도 `T1` 뿐이므로 `G₀` 와 `c(R)` 이 불변이다.
> 2. 비용 0 이 아닌 모든 호는 비용 ≥ 1 이다 (`cost` 의 정의).
> 3. 라운드-107 보조정리 7 은 **임의의 비음 비용**에 대해 서술돼 있으므로
>    `총비용 ≥ c(R) − 1` (무료 진입이 없으면 `c(R)`) 이 성립한다.
> 4. 보조정리 6 은 `Σ cost(ω) ≤ B` 를 준다 (§5 에서 `cost` 가 정확함을 확인).
> 5. 인증서는 그 5,043 상태의 **모든** cover 의 **모든** 배정에서 `c(R) − 1 > B` 를
>    기록한다. 3·4 에 모순. ∎
>
> 이 증명 어디에도 네-joint 이동 집합이 쓰이지 않는다 — 1·2 가 그것을 대신한다.
