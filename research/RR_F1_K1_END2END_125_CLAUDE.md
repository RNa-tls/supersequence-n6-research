>
> Codex 가 **`F`(abandonment 수)와 `G`(다중도 초과 `= P − 120`)의 동일시를 반증**했다.
> 두 양은 `F ≤ G` 만 만족하고 일반적으로 다르다(`n = 4` 합법 walk 29,255개 중 **2,088개**에서

> 받아들이며 **`abandonment` 를 계산조차 하지 않는다**(문자열 `abandon` 이 0회).

> `F = 1` 이면서 `G ≥ 2` 인 walk(존재한다 — `n=4` 에 46개)은 `P = 122` 라 애초에 영역 밖이고,
> 정정된 `(k, G)` 매개화에서 **`G = 2` 열**에 속한다(그 열은 열려 있다).
>
> **계산 사실은 하나도 바뀌지 않는다** — 260 실행 · 전부 `UNSAT_COMPLETE` · 캡 0 · SAT 0 ·
> 295,093,380,933 노드.  바뀌는 것은 **이름**이다: 이 라운드는
> **`(k, G) = (1, 1)` 을 닫았고**, 그것이 정정된 55칸 `(k, G)` 표의 한 칸이다.

## 1. 자원 표를 처음부터 다시 셌다 (§1)

라운드 122 의 수를 **상속하지 않고** 다시 유도했다.

    F = 1, k = 1  ⇒  P = 121,  O = 25,  D = 5O − P = 4
    r = O + e = 25 + e                         (run 개수)
    S = (r − 1) + x − f_out = 24 + e + x − f_out
    N = S + F − O = S − 24 = e + x − f_out
    L = 844 + F + S + H = 845 + S + H = 869 + N + H
    L ≤ 871  ⟺  N + H ≤ 2  ⟺  e + x + H − f_out ≤ 2
    보조정리 E: f_out ≤ 1 + e          f_out ≤ 2 (짧은 pass 가 둘뿐)
    run 결손 = 5r − P = D + 5e = 4 + 5e

전수 열거 결과:

| 값 | 라운드 125 재계산 | 라운드 122 보고 |
|---|---|---|
| 자원 행 `(e,x,f_out,H)` | **50** | 50 |
| 하위경우 (행 × 무거운 조성) | **61** | 61 |
| 조각 용량으로 탐색 없이 죽는 하위경우 | **9** | 9 |
| 살아남는 하위경우 | **52** | 52 |
| 살아 있는 하위경우를 가진 행 | **44** | 44 |

**라운드 122 의 수는 일관되어 있었다.** 용어가 애매하다는 우려는 근거가 없었다 —
"행" 은 `(e,x,f_out,H)`, "하위경우" 는 거기에 무거운 무게 다중집합을 곱한 것이다.

경계값도 **가정이 아니라 유도**된다: `max H = 3`, `max e = 4`, `max x = 3`.

## 2. `H` 의 정확한 분류 (§2)

`H = Σ (w−3)₊` 이고 이음매 무게는 6 이하이므로 한 이음매의 기여는 `p = w − 3 ∈ {1,2,3}`.

| `H` | 무거운 조성 | 행 수 | 하위경우 | 살아남음 |
|---|---|---|---|---|
| 0 | `[]` | 26 | 26 | 22 |
| 1 | `[4]` | 15 | 15 | 13 |
| 2 | `[5]`, `[4,4]` | 7 | 14 | 12 |
| 3 | `[6]`, `[5,4]`, `[4,4,4]` | **2** | 6 | **5** |

**`H ≤ 3` 은 가정이 아니다.** `H = 4` 는 `e+x ≤ f_out − 2` 를 요구해 `f_out = 2`,
`e = x = 0` 이 되는데 보조정리 E 가 `f_out ≤ 1` 을 강제해 모순이다.

**`H = 3` 인 행은 딱 둘이다**: `(e,x,f_out) = (0,0,1)` 과 `(1,0,2)`. **둘 다 `N = −1`.**

그리고 결정적으로 — `H = 3` 의 `[6]` 조성은 행 `(0,0,1)` 에서 **탐색 없이 죽는다**
(조각 4개, 용량 106 < 121).  따라서 **무게-6 이음매는 칸 전체에서 딱 한 하위경우
`(e,x,f_out,H) = (1,0,2,3)` 에만 나타난다.**

## 4. 무게-6 기하 — 그리고 **목록 자체의 정정** (§4)

무게-6 은 이전 어느 `F=1` 칸에서도 하중을 받지 않았다(`(4,1)`·`(3,1)`·`(2,1)` 은 `H ≤ 2`).
일반 `(1,1)` 에서 처음으로 실제로 쓰이므로 무게-4/5 와 같은 기준으로 census 했고,
그 과정에서 **목록이 퇴화한다**는 것을 발견했다.

> ### 정정 상자 — 무게-6 tail 은 461개가 아니라 **308개**다
>
> `w < 6` 이면 action 이 `z[:6−w] = y[w:]` 를 강제하므로 `ω(y,z) = w` 가 **항상** 성립한다
> (실측 13/13, 71/71 — 증명도 한 줄이다: `z[i] = y[w+i]` 와 `z[i] = y[k+i]` 를 비교하면 `k=w`).
>
> `w = 6` 은 강제 접두가 **비어 있어** `z = y∘π` 이고, `π` 가 `{0..5}` 에서 분해불가여도
> `ω(y,z) < 6` 일 수 있다.  `ω = k < 6` 은 `π(i) = k+i (i ≤ 5−k)` 와 동치이고, 그러면
> `π` 의 마지막 `k` 자리가 정의하는 안쪽 순열 `σ` 에 `π` 의 분해불가성이 **아무 제약도 주지
> 않는다** — 실제로 `k!` 개가 전부 나타난다.
>
> | | 개수 | 정체 |
> |---|---|---|
> | `ω = 6` | **308** | **진짜** 무게-6 이음매 |
> | `ω < 6`, `σ` 분해불가 | **89** | 실제로는 더 가벼운 **진짜** 이음매. `1+1+3+13+71 = 89` 로 `w ≤ 5` 목록과 정확히 일치하고 같은 `y` 에서 같은 `z` 를 낸다 |
> | `ω < 6`, `σ` 분해가능 | **64** | 12글자 창 안에 **중간 순열**이 들어간다 — 단일 이음매가 아니라 pass 둘. `Σ (k! − indec(k)) = 1+3+11+49` |
>
> 엔진은 **308개만** 제공한다.  89개는 가벼운 목록이 이미 **올바른 비용으로** 제공하므로
> 잃는 것이 없고, 64개는 애초에 합법 전이가 아니다.  **거짓 기각 0.**
>
> **라운드 123 에 대한 영향**: 뿌리 열거기는 461개를 전부 달았으므로 `H = 3` 셀의 뿌리 수는
> **과다 계수**다. 완전성 주장은 **영향 없다**(초집합도 완전하다). 뿌리 수는 상한으로 읽어야 한다.
> **라운드 124 에 대한 영향**: **없다** — 측정한 부분가족이 전부 `H ≤ 2` 라 `hub ≤ 2` 였고
> 무게-6 은 한 번도 제공되지 않았다.

정정 후의 census 는 무게-4/5 와 완전히 평행하다:

| 무게 | 진짜 이음매 | 클래스 | all-or-nothing | 원천 육각형 복귀 | `ℓ=5` 겹침 분포 |
|---|---|---|---|---|---|
| 4 | 13 | 9 | 예 | **없음** | 0:9, 1:3, 5:1(=`W4_0`) |
| 5 | 71 | 20 | 예 | **없음** | 0:64, 1:6, 5:1(=`W5_0`) |
| 6 | **308** | 38 | 예 | **없음** | 0:280, 1:25, 2:3 |

**무게-6 의 궤도 내부 이음매는 `ℓ ∈ {1,2,3}` 에서만 나온다** — `(W6_1, ℓ1, +2)`,
`(W6_5, ℓ2, +3)`, `(W6_21, ℓ3, +4)`, `(W6_107, ℓ1, +3)`, `(W6_125, ℓ2, +4)`,
`(W6_221, ℓ1, +4)` 여섯 개뿐이고 **`ℓ = 5` 에는 하나도 없다.**  즉 **full pass 뒤의
무게-6 이음매는 언제나 궤도를 바꾼다.**  무게-4/5 와 정반대다(그쪽은 `ℓ=5` 에만 있다).

## 5. 끝까지 도는 상태 (§5) — 그리고 §8 의 내부 전이

뿌리를 열거하지 않는다.  `initial_state` 에서 바로 시작해 121 pass 까지 간다.
라운드 124 의 서명 분석이 준 결론 — 이력 순서는 필요 없고 소비된 육각형 집합이 필요하다 —
을 그대로 반영해 다음만 들고 다닌다:

    현재 단어 u, 현재 pass 길이 len
    사용 육각형 120비트 (HLO/HHI), 궤도별 phase 마스크 omask[144]
    짧은 pass 상태 sstate ∈ {0,1,2}, h* 의 진입 단어 vword 와 분할 b
    예산 cost(=S) · hub(=H) · x · f_out · e(=rev) · runs · orbits
    D 회계용 defcnt[5] · blk/freshcnt · EXC 용 mcnt[120]

**이력 순서는 저장하지 않는다.**  `runlen`·`shrun`·`segpasses`·`segsh` 는 프룬 회계일 뿐이다.

첫 짧은 pass `X` 는 **DFS 안의 상태 전이**다 (§8): `sstate 0 → 1` 에서 `F` 가 1 이 되고
`h*` 와 `b` 가 고정되며, `sstate 1 → 2` 는 두 번째 방문 `Y` 로 **단어가 강제된다**
(`w == σ^b(vword)`, 길이 `6−b`).  그 뒤로는 `F` 가 더 오를 수 없다.
**뿌리를 방출하지 않으므로 라운드 123 의 `10¹¹` 뿌리 폭발이 일어나지 않는다** (§21).

## 6. `D = 4` 를 최대한 쓴다 (§6)

    k=4: D=19    k=3: D=14    k=2: D=9    **k=1: D=4**

`D` 는 **궤도 결손의 총합**이므로 25개 궤도 중 **적어도 21개가 full**(pass 5개)이다.
매 노드에서 (a) 지금까지 확정된 결손 `dcommitted`, (b) 아직 열지 않은 궤도가 반드시
추가할 결손 `freshdeficit`(신선 궤도의 육각형이 이미 막힌 개수로 계산), (c) 남은 run 예산
을 합쳐 **최종 `D` 가 4 에 도달 불가능하면 가지친다.**  `run 결손 = 4 + 5e` 도
`RMAX = 25 + e` 로 정확히 고정된다.

## 7. 라운드 123 접두 정리를 **프룬으로** 쓴다 (§7)

뿌리를 만들지 않는다.  `X` 이전의 모든 pass 가 full 이라는 사실은 `sstate == 0` 분기가
full pass 만 잇는 것으로 그대로 들어간다.

**증명된 것과 관측된 것을 갈랐다.**  라운드 123 에서 `e = x = H = 0` 의 `q ≤ 46` 은
`NTAB[4] = 46` 이라는 **해석적 상한**과 전수 열거가 독립으로 일치하므로 **증명됐다**.
축마다의 `+15`/`+20` 증가와 전체 `q ≤ 114` 는 **관측**이고 증명이 아니다.
**따라서 이 라운드는 어떤 `q` 상한도 프룬으로 쓰지 않는다** — 증명된 `NTAB` 조각 용량만
쓴다(그것은 walk 전체에 대한 정리이지 접두 길이 가정이 아니다).

## 8. 두 번째 짧은 pass 의 의무 (§9)

`X` 가 놓이면 `h*` 의 두 번째 방문 `Y` 는 **단어까지 강제**된다: 진입 단어 `σ^b(v)`,
길이 `6 − b`.  엔진은 그 단어가 실제로 나올 때만 `sstate 1 → 2` 를 허용한다.
Q2 의 fragment-locality 는 쓰지 않는다.

## 9. 반전 `Φ` (§10)

**쓰지 않았다.**  라운드 120/121 이 증명한 범위는 "`X` 의 탈출 이음매가 자유(`ω=2`)일 때
`Φ` 가 `O` 를 보존한다" 이고, 일반 `(1,1)` 의 52개 행 중 그 조건이 모든 walk 에 대해
성립하는 행만 골라 접으면 이득이 작다.  `b ≤ 3` 으로 **전역 접기는 하지 않았고**
`b = 1..5` 다섯 갈래를 전부 돌렸다.  `SEAM`·`PMAX`·`SYMCUT`·`REVONLY`·`YFRESH`·`YGAP`·
`YGAPMIN` 도 전부 껐다 — **증명 부담을 하나도 지지 않는다.**

## 10. 해석적 폐쇄 (§11, §12)

`run 결손 = 4 + 5e` 이므로 `e = 0` 이면 결손이 **4 뿐**이고

    BESTSEG[m][4] = 20m + 26   (m ≥ 2),   BESTSEG[1][4] = 46

이라 `m ≤ 4` 는 최대 **106 pass** — `P = 121` 에 못 미친다.  조각 수는
`m = 1 + (2 + x + e + h)` 이므로 `e = 0` 에서 `x + h ≤ 1` 인 하위경우는 **전부 죽는다.**

**탐색 없이 죽는 9개 하위경우:**

| `(e,x,f_out,H)` | 무거운 조성 | 조각 `m` | 용량 |
|---|---|---|---|
| `(0,0,0,0)` | `[]` | 3 | 86 |
| `(0,0,1,0)` | `[]` | 3 | 86 |
| `(0,1,0,0)` | `[]` | 4 | 106 |
| `(0,1,1,0)` | `[]` | 4 | 106 |
| `(0,0,0,1)` | `[4]` | 4 | 106 |
| `(0,0,1,1)` | `[4]` | 4 | 106 |
| `(0,0,0,2)` | `[5]` | 4 | 106 |
| `(0,0,1,2)` | `[5]` | 4 | 106 |
| `(0,0,1,3)` | **`[6]`** | 4 | 106 |

`e = 1` 이면 결손이 9 가 되어 `BESTSEG[m][9] = 20m + 52 (m ≥ 2)` 이고 `m ≥ 4` 는 항상
성립하므로 **`e ≥ 1` 에서는 해석적으로 죽는 하위경우가 없다.**

## 11. 무거운 조건화 (§13) 와 `H = 3` (§14)

13 + 71 + 308 개를 아무 노드에서나 제공하지 않는다.  실행마다 무거운 **무게 다중집합을
정확히 고정**한다: `HW`(무게 비트마스크) · `HCAP = HUBMIN = H`(그래서 `hub` 가 정확히 `H`) ·
`HJCAP =` 무거운 이음매 개수.  일곱 다중집합 `[] · [4] · [5] · [4,4] · [6] · [5,4] · [4,4,4]`
이 서로 겹치지 않게 `H` 를 나눈다.

`H = 3` 세 갈래는 따로 분석했다.

* **A. `[6]`** — 살아남는 하위경우가 **딱 하나** `(e,x,f_out) = (1,0,2)` 다.
* **B. `[5,4]`** — `(0,0,1)` 과 `(1,0,2)`.
* **C. `[4,4,4]`** — `(0,0,1)` 과 `(1,0,2)`.

## 12. 음수 `N` 은 하중을 받는다 (§15)

`N = e + x − f_out < 0` 은 `f_out > e + x` 를 뜻하고, 보조정리 E `f_out ≤ 1+e` 와 합치면

    f_out = 1 ⇒ e = x = 0            (N = −1)
    f_out = 2 ⇒ e ≥ 1 이고 e + x ≤ 1 ⇒ e = 1, x = 0   (N = −1)

**따라서 `N ≥ −1` 이고, `N = −1` 은 정확히 위 두 경우이며 둘 다 `x = 0` 이다.**

`H = 3` 은 `N + H ≤ 2` 에서 `N ≤ −1` 을 요구하므로 **모든 `H = 3` walk 은 `x = 0`** 이다 —
즉 **비용-1 이음매가 하나도 궤도 내부일 수 없다.**  §4 와 합치면: `H = 3` walk 의 무거운
이음매는 전부 궤도를 **바꾼다**.  이것이 `H = 3` 이 폭발하지 않은 구조적 이유다.

## 13. 최종 그룹 표 (§16)

**52개 살아 있는 하위경우 각각이 하나의 최종 그룹**이고, 각 그룹은 `b = 1..5` 다섯 실행으로
나뉜다 — 총 **260 실행**.

극대 `(e,x)` 상자로 뭉치는 것도 시도했지만 **버렸다**: 상자로 뭉치면 `FOUTMIN` 을 쓸 수 없고
(상자 안의 더 작은 walk 을 잘못 버린다) 프룬이 크게 약해진다.  실측으로 극대 상자
`H0_e4_x0` 는 2×10⁹ 노드에서 **캡에 걸리는데**, 같은 경우를 정확한 행 `(4,0,2)` 로 돌리면
**5.04×10⁸ 노드에 완주**한다.

**덮개 논증 (거짓 기각 0).** 어떤 walk 이든 정확한 `(e*, x*, f*, H*, 다중집합*)` 을 갖고
그것이 61개 하위경우 중 하나다.  9개는 §10 에서 **탐색 없이** 불가능하고, 나머지 52개는
각각 자기 실행에서 잡힌다 — `ECAP = e*`, `XCAP = x*`, `FOUTCAP = FOUTMIN = f*`(그래서
`f_out` 이 정확히 고정), `HCAP = HUBMIN = H*`(그래서 `hub` 가 정확히 고정),
`HW`/`HJCAP` 로 다중집합 고정.  `b` 는 다섯 갈래 전부 돈다.  **누락이 없다.**

엔진 인자는 전부 정확하다: `ORBCAP = 25`(잎에서 `orbits == 25` 를 요구) · `DCAP = 4` ·
`EXCCAP = 5` · `SHCAP = 26`(**`cost + hub ≤ 26 ⟺ L ≤ 871`**, 길이 조건은 이것 하나다) ·
`COSTCAP = 24 + e + x − f_out`(= 그 행의 `S`) · `RMAX = 25 + e`(⇒ `SHRUNCAP = 4 + 5e`) ·
`FOD = 1`.

## 15. 양성 대조 (§18)

* **다섯 짧은 분할** `b = 1..5` 를 전부 돌렸다 (접지 않았다).
* **첫 pass 가 full 인 구조**: 엔진은 첫 pass 가 full 인 분기와 짧은 분기를 **둘 다** 연다
  (`firstIsShort` 루프).  라운드 122 의 `n=4` 전수(첫 pass full 72%)와 모순되지 않는다.
* **양 끝이 full 인 구조**: 마지막 pass 가 full 인 walk 도 잘리지 않는다 —
  `SEAM`/`SYMCUT`/`PMAX` 가 전부 꺼져 있다.
* **모든 `H` 조성**: 일곱 다중집합 전부에 실행이 있다.
* **무게-4/5/6 대표 클래스**: `HW` 가 그 무게를 켜면 그 무게의 **모든** tail 이 제공된다
  (와일드카드 없음).

**거짓 기각 = 0.**

## 17. SAT 처리 (§22) 와 UNKNOWN 처리 (§23)

**SAT 는 하나도 나오지 않았다.**  나왔다면 그 그룹을 멈추고 121-pass 전체 수열 · 구체적
단어 · `h*` · `X`/`Y` · `b` · `e`/`x`/`f_out` · `N`,`H`,`D` · 모든 무거운 tail 과 위치를
보존한 뒤 literal NR6 의미로 재생할 준비가 되어 있었다 (엔진은 `witness_words` ·
`witness_lengths` 를 출력한다).

**캡/타임아웃도 하나도 없었다.**  260 실행 전부 `UNSAT_COMPLETE` 다.  캡에 걸렸다면
`UNKNOWN` 으로 남기고 `UNSAT` 으로 승격하지 않았을 것이다 — 파일럿 단계에서 실제로
그렇게 처리했다(극대 상자 10/14 가 캡에 걸렸고, 닫혔다고 **추론하지 않았다**).

## 18. 라운드 123·124 에 대한 영향

* **라운드 123 (뿌리 완전성)** — 뿌리 열거기가 무게-6 을 461개 전부 달았으므로 `H = 3`
  셀의 **뿌리 수는 과다 계수**다.  **완전성 정리는 영향이 없다**(초집합도 완전하다).
