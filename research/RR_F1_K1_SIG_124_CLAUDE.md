>

## 1. 미래 동치의 정의 (§2)

뿌리 `r` 은 "첫 짧은 pass `X` 를 막 확정한 시점의 부분 walk" 다. `Suf(r)` 을 `r` 을 접두로
갖는 **합법적 완성의 접미사 집합**이라 하자. 두 뿌리 `r₁, r₂` 가 **미래 동치**란
`Suf(r₁) = Suf(r₂)` 를 말한다.

찾는 것은 함수 `Sig` 로서

> **`Sig(r₁) = Sig(r₂) ⟹ Suf(r₁) = Suf(r₂)`**

를 만족하는 것이다. 이 함의가 하중을 받는다(load-bearing): 역방향은 필요 없다 — `Sig` 가
동치류보다 잘게 쪼개도 **건전**하고, 다만 압축률만 손해다. 그러므로 §18 에서 재는 압축률은
**참 동치류 개수의 하한**이 아니라 **상한을 향한 근사**이며, 이 구별 때문에 §18 의
CEILING 실험이 필요하다.

## 2. 충분한 서명 — 그리고 왜 각 좌표가 빠지는가 (§1, §3, §4)

**정리 124.1 (충분성).**
`Sig(r) = ( v, b, omask, cost, hub, x, e )` 이면 `Sig(r₁) = Sig(r₂) ⟹ Suf(r₁) = Suf(r₂)`.

*증명 스케치.* 접미사가 합법인지 판정하는 데 필요한 정보는 정확히 세 가지다.

1. **지금 어디인가.** 다음 pass 는 `X` 의 탈출 단어에서 출발하고, `X` 의 탈출 단어는
   `σ^{b−1} v` 다. 또 `(v,b)` 는 `X` 가 남긴 미완성 의무 `h*`(두 번째 방문 단어
   `σ^b v` 와 그 잔여 길이 `6−b`)를 전부 결정한다. 그러므로 `(v,b)` 가 위치와 의무를 다 준다.
2. **무엇이 소비됐는가.** 미래의 pass 는 아직 진입으로 쓰이지 않은 단어에서만 시작할 수
   있다. 소비된 진입 단어 집합은 `omask` 가 정확히 준다 (§3).
3. **예산이 얼마나 남았는가.** `cost`(= `Σ(ω−3)₊` 의 누적 + 무거운 joint 개수), `hub`,
   `x`, `e`. `(1,1)` 칸의 상한은 `L = 869 + N + H ≤ 871`, 즉 `e + x + H ≤ 2 + f_out` 이고
   뿌리에서 `f_out = 0` 이다.

빠진 좌표는 전부 위 셋에서 **파생**되거나 **미래에 영향이 없다**:

| 좌표 | 왜 빠지는가 |
|---|---|
| `usedhex` (120비트) | 진입 단어 ↔ `(궤도, phase)` 가 720↔720 **전단사**이므로 `omask` 가 진입 단어 집합을, 따라서 사용 육각형 집합을 결정한다. **파생값.** |
| `orbits`, `runs`, `defcnt`, `EXC`, `mcnt`, `blk`, `freshcnt` | 전부 `omask` (와 그로부터 나오는 사용 육각형 집합)의 함수다. 특히 `runs = orbits + e`. **파생값.** |
| `runlen` | 한 궤도에 phase 가 5개뿐이라 run 이 5 pass 를 넘는 것은 phase 단사성이 이미 금지한다. `shrun` · 조각 용량에서의 나머지 쓰임은 **프룬 회계**이지 합법성 조건이 아니다. **미래 언어에 영향 없음.** |
| `f_out` | 짧은 pass 의 탈출에서만 생기는데, 뿌리 시점에 `X` 의 탈출은 아직 고르지 않았다. 모든 뿌리에서 **0**. |
| `D = 5O − P` | `P = 121` 이 고정이므로 `D = 4 ⟺ O = 25`. **독립 제약이 아니다** — `O` 를 다시 쓴 것일 뿐. |
| 접두의 **순서/이력** | 위 셋에 안 나온다. **필요 없다.** |

## 3. 구조 보조정리 — phase 단사성은 육각형 단사성의 **따름정리**다

`src/verify_f1_k1_sig_124.py` 의 `orbit_hexagon_facts()` 가 파이썬에서 기하를 처음부터
다시 만들어 전수 확인한 값:

| 사실 | 값 |
|---|---|
| 궤도 수 / 육각형 수 | 144 / 120 |
| 5개 phase 가 서로 다르지 **않은** 궤도 | **0** |
| 5개 단어가 서로 다른 육각형 5개에 있지 **않은** 궤도 | **0** |
| 서로 다른 궤도 6개를 만나지 **않는** 육각형 | **0** |

따라서 한 궤도의 다섯 단어는 **서로 다른 다섯 육각형**에 놓인다. 결과로

> **"쓸 수 있는 진입 단어" = "아직 안 쓴 육각형의 단어".**
> phase 별 별도 장부는 합법성에 필요 없다.

이것이 §15 의 coarse 서명(§4)을 정당화한다.

## 4. 세 가지 서명 (§8, §15, §16)

| 서명 | 내용 | 건전한가 |
|---|---|---|
| **fine** | `(v, b, cost, hub, x, e, {(q, omask[q]) : omask[q] ≠ 0})` | **예** (정리 124.1) |
| **coarse** | `(v, b, cost, hub, x, e, usedhex 120비트, 열린궤도 144비트)` | **예** — fine 의 몫. §3 에 의해 육각형 집합이 합법성을 다 주고, 열린 궤도 집합은 `O = 25` 세기에만 쓰인다 |
| **CEILING** | `(v, b, usedhex 120비트)` | **아니다 — 진단 전용.** 예산 전부와 열린-궤도 집합을 버렸다 |

CEILING 은 **일부러 건전하지 않게** 만들었다. 그 목적은 하나다: 어떤 건전한 서명도
CEILING 보다 더 거칠 수 없으므로, **CEILING 의 압축률이 곧 압축 가능성의 상한**이다.
CEILING 이 ×1.19 라는 것은 "더 똑똑한 서명을 찾으면 된다" 는 길이 **막혔다**는 뜻이다.

`(v, b)` 를 이렇게 다루는 것이 정당한 이유는 §2 의 (1) 이다: `(v,b)` 가 `h*`, 두 번째
방문 단어 `σ^b v`, 그 잔여 길이 `6−b`, `X` 의 탈출 단어 `σ^{b−1} v` 를 **전부** 결정한다.

## 5. 정확 비교 해시 — 충돌로 인한 가짜 압축은 없다 (§8)

서명 개수를 해시로 세면 **충돌이 압축률을 부풀린다**. 그래서
`src/f1_k1_sig_124.c` 는 열린 주소법 테이블의 각 슬롯에 서명 **바이트열 전체를 아레나에
저장**하고 `memcmp` 로 확인한다. 서로 다른 두 서명이 병합되는 일은 구조적으로 불가능하다.
탐침이 테이블을 한 바퀴 돌면 `probe_overflow` 로 보고하며, 열 실행 전부 **0** 이었다.

뿌리는 **저장하지 않는다.** 1.45×10¹¹ 개의 파이썬 객체를 만들지 않았다 (§7 지시).

## 6. 뿌리가 여러 번 생성되는가 (§7)

`e2_x0_H0` 에서 뿌리 11,485,015 개에 fine 서명 11,484,670 개 — 차이 **345**. 즉 서로 다른
접두가 같은 미래 상태로 합류하는 일은 **일어나긴 하지만 10⁻⁵ 수준**이다. `H ≥ 1` 셀에서
비율이 ×1.09 → ×1.18 로 오르는데, 이는 무거운 tail 이 같은 육각형 집합에 서로 다른 경로로
도달할 수 있기 때문이다. 그래도 상한이 ×1.19 다.

## 7. 첫 표적: 강체 셀 (§13)

`e = x = H = 0`: 접두 상태 3,425 · 뿌리 17,545 · 최대 `q` = 46.
서명 개수 = **17,545 = 뿌리 개수**. 압축률 **정확히 ×1.00** — 강체 셀에서는 **모든 뿌리가
서로 다른 미래 상태를 갖는다.** 여기서 이미 답이 나왔다고 볼 수 있고, 나머지 아홉 실행은
"예산을 열면 합류가 생기지 않을까" 라는 유일하게 남은 희망을 잰 것이다.

라운드 123 과의 재생 대조: 뿌리 17,545 · 접두 3,425 · 최대 `q` 46 — **세 값 모두 일치**.

## 8. 한-예산 섭동 (§14)

`e1` / `x1` / `H1` 을 각각 하나씩 열었다. `e` 축은 압축이 **전혀** 없고(×1.00),
`x` 축은 coarse 에서만 ×1.03, `H` 축이 유일하게 fine 에서 ×1.09 를 준다. 두-예산
섭동(`e2`, `e1x1`, `x2`, `e1H1`, `x1H1`, `H2`)에서도 최대가 ×1.18 이다. **`H` 축만이
압축을 만들고, 그 축조차 상수배에서 멈춘다.**

## 9. 왜 이것이 "충분성" 을 무너뜨리지 않는가 (§9)

압축이 없다는 것은 서명이 **틀렸다**는 뜻이 아니다. 정리 124.1 은 여전히 성립한다 —
서명은 충분하다. 측정이 말하는 것은 다른 명제다:

> **충분한 최소 상태가 이미 뿌리 개수만큼 많다.**

즉 `Suf(r₁) = Suf(r₂)` 인 뿌리 쌍이 거의 없다. 이는 기하적으로 자연스럽다: 뿌리는
20~46 개의 pass 로 육각형을 소비하고, 서로 다른 소비 패턴은 남은 육각형 집합을 실제로
다르게 만들며, 남은 육각형 집합이 다르면 미래에 쓸 수 있는 진입 단어 집합이 다르다.

## 10. Q2 눈금 맞추기 (§10)

역사적 Q2/Area-A 는 상태 **6,396** 개였다. 강체 셀만 해도 뿌리가 17,545 개이고 서명도
17,545 개다. `H = 2` 를 열면 서명이 3.8×10⁷ 개다. **현재의 조건부 Q2/Area-A 전결합
모형 안에서** Q2 가 작았던 이유는 압축이 잘 돼서가 아니라 **뿌리 가정이 좁았기
때문**이다 (라운드 122 가 이미 보인 대로: 일반 `(1,1)` 은 Q2 로 환원되지 않는다).
Q2 는 5개의 `short_ell` 뿌리에서 출발하고 RR 매크로 알파벳이 `ω ≥ 4` 를 전부 잘라내며
`P ∈ {13,14}` 로 묶여 있다. 일반 `(1,1)` 에는 그 셋 중 어느 것도 없다.
**"Q2 가 증명됐다" 고 말하지 않는다.**

## 12. BDD / ZDD (§16) 와 frontier-DP (§17)

**§16 (결정 다이어그램).** 서명의 본체는 120비트 육각형 집합이다. ZDD 로 육각형 집합족을
나타내면 공유가 생길 수 있지만, 공유의 상한은 **서로 다른 집합의 개수**가 아니라
**미래가 실제로 같아지는 정도**로 결정된다. CEILING 실험이 바로 "육각형 집합만 남기고 다
버리면 얼마나 줄어드나" 를 잰 것이고 답이 ×1.19 다. 그러므로 ZDD 로 노드 공유를 얻더라도
**탐색해야 할 서로 다른 미래는 줄지 않는다.** 다이어그램은 저장 문제를 풀지 탐색 문제를
풀지 않는다.

**§17 (frontier-DP).** 접두 서명 `PSig = (u, omask, cost, hub, x, e)` 를 따로 셌다.
접두 상태 대비 서로 다른 접두 서명의 비율은 강체 ×1.00, 최대 ×1.18 이다.
**프런티어에서 접두를 합치면 없어지는 일이 거의 없다.** frontier-DP 도 이득이 없다.
