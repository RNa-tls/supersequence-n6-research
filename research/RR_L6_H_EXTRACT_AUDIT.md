## Phase 2 — Claim 1–5 의 재구성

`r156/THEOREM.md` §3–§4 에 진술과 종이 증명을 실었다.  요지:

| | 진술 | 필요한 가설 |
|---|---|---|
| C1 | `sum P_i = P - (n-1)c` | 보조정리 E (순수 순환 = 궤도 전체) |
| C2 | `sum D_i = (n-1)k - G + (n-1)sigma` | C1 + 정의뿐 (**추가 가설 없음**) |
| C3 | `blocks_i = O_i + tok_i`, `sum tok_i = B* - sigma` | clean E 가 궤도를 보존 (카탈로그), clean E 를 자르지 않음 |
| C4 | `0 <= sigma <= B*`, 사슬 1 개 ⟹ `sigma = 0` | 보조정리 E + C3 |
| C5 | `sum rep_i <= R_int`, 유지 A/B 가 각각 하나씩 | 사슬이 성분의 부분경로, A/B 가 같은 육각형 |

C2 는 C1 의 **순수한 따름정리**임을 확인했다:
`sum D_i = r·sum O_i − sum P_i = rO − HEX − G + r·sigma` 이고
`rO − HEX = rk` 이므로 `n` 과 무관한 항등식이다.

## Phase 3 — pass 생성 (입력층 재검증)

`r156/src/passes156.py` 가 보조정리 A–D 와 카탈로그 은닉창 수를 정의에서 다시

### 5.3 문서에 적힌 절차 ≠ 구현된 절차  ← **핵심 결함**

원문 (`src/l6_extraction_145.py` 18–22 행):

> "Delete the c pure circuits.  The remaining `K - c = d + 1` beta components
> are cycles; open each at one non-E edge (a nonpure cycle has one by
> definition).  Then cut the h heavy joints. … the result is `d + 1 + h`
> paths"

`r149/PROOF.md` §3 3–5 단계도 같은 문장이다.  그런데 `d+1` 개 성분 중 **하나는
더미 꼭짓점 `*` 을 품은 `Y_*`** 이고,

* `*` 은 pass 가 아니다 — 포트도, 궤도도, 육각형도 없다;
* `Y_*` 는 **비-E 간선을 가질 필요가 없다**.

`r156/src/prose156.py` 가 세 판본을 실제 덮개에서 돌려 비교했다

| 판본 | 뜻 | 결과 |
|---|---|---|
| `impl` | 구현: `*` 삭제로 `Y_*` 를 열고, 개방은 `d` 회 | **794/794 건전** |
| `proseA` | 글자 그대로: `Y_*` 도 비-E 간선에서 개방하고 `*` 은 버림 | **523/754 에서 사슬 수가 모형 상한 `d+1+h` 초과** |

가장 단순한 반례는 `n=4` 최적해 자체다: `d=0, h=0` 이라 모형 상한은 사슬
**1 개**인데 `proseA` 는 **2 개**를 만든다.

`proseA` 의 방향이 특히 나쁘다 — 사슬이 모형이 허용하는 개수보다 많으면

```

proseA  : 사슬 2 개  > 모형 상한 1                   (상한 논증 붕괴)
```

**수리**: `Y_*` 는 꼭짓점 `*` 을 삭제함으로써 열리고, 개방은 `d` 회다.

### `e <= Z - Qs` — 원문 유도의 빈틈과 수리

`r149/PROOF.md` §3 은

> `e <= 2g − D2 − Qs = Z − d − Qs <= Z − Qs`

로 유도한다.  첫 등호는 `a = D2` **그리고** `bb = Qs` 일 때만 성립한다.
일반적으로 `a < D2` 이면 `e <= 2g − a − bb` 가 더 **크다**.  올바른 유도는
한 단계를 더 요구한다:

> type A 는 무게 2, type B 는 무게 3 이므로 **A/B 간선은 heavy 절단 대상이
> 아니다**.  따라서 살아남지 못한 A/B 간선은 반드시 **개방 간선**이고, 개방은
> 정확히 `d` 개이므로 `(D2 − a) + (Qs − bb) <= d`.  그러면
> `e <= 2g − a − bb = 2g − D2 − Qs + [(D2−a)+(Qs−bb)] <= 2g − D2 − Qs + d
>     = (z − d) − D2 − Qs + d = Z − Qs`.

결론은 참이다: 실제 덮개 7,120 회에서 `e <= Z − Qs` 위반 0 이고, `e > 0` 인
사례가 2,115 회, `e` 를 1 만큼 조인 돌연변이(M5)는 577 회 검출된다.
**이 수리는 `H.extract` 의 절단 규칙(“잘린 A/B 는 개방뿐, 개방은 d 개”)에
의존하므로, H.envelope 의 봉투는 H.extract 의 절단 절차에 실제로 적재되어
있다.**  (H.envelope 자체는 이 감사의 범위 밖이다.)

## Phase 9 — 완화 방향

각 변환: pass 생성 = 동치, 성분 분해 = 분할, `*` 삭제 = 포트 아닌 꼭짓점 삭제,
순수 순환 삭제 = 정확한 삭제(정확히 `5c` 포트, `required` 에 반영),
개방·heavy 절단 = 간선 삭제.  **어느 단계도 포트를 만들거나 복제하지 않는다.**

모형이 실제보다 **많은** 사슬을 쓰는 것이 건전한 이유도 확인했다:
`best(n, …)` 는 `n` 에 대해 비감소이고 (`cap(0,0,0,0,0) = 20 >= 0`),

## Phase 10 — 완비성: 실제 덮개 → 모형 방향 (명시)

먼저 **사슬이 카탈로그 위의 워크라는 것**부터 확인한다.  `structure()` 는 모든
재배정 접합에 대해 (i) 출발 문자열이 `end(v_{nu(i)})` 임(보조정리 C)과
(ii) `gap = omega(end(v_x), v_{beta(x)})`, 즉 **최단 연결자**임을 강제하고,
위반 시 예외를 던진다.  따라서 사슬의 연속 쌍 `(x, beta(x))` 은 전부 "완전
pass 끝점에서 나가는 최단 연결자" 카탈로그의 간선이고, 사슬은 그 카탈로그
위의 워크다 — 이것이 용량 모형이 값을 매기는 대상과 같은 객체다.

> **명제.**  좌표행 `C` 를 실현하는 고정 대표원이 존재하면, 그 추출은 `C` 의
> 모형에 **허용되는 배치**를 주며 그 배치의 포트 합이 `required(C)` 다.
> 따라서 `bound_M(C) < required(C)` 는 `C` 를 실현하는 덮개가 **없음**을 뜻한다.

증명은 Claim 1–5 + (6) + (7) 이 곧 "배치가 허용된다"는 진술이라는 것이다
(위 표).  이 방향은 반증 가능해야 의미가 있으므로, 실제 객체로 시험했다:

**872 증인의 행이 실제로 열거되고 배제되지 않는가?**

```
행 (t=5): k=5 Z=0 H=0 B*=0 G=25 g=0 c=25 d=0 D2=0 Qs=0 h=0, s=sigma=0
required = 120 + 25 − 125 = 20
모형 사슬 수 = d+1+h = 1,  b_sum = 0,  D_sum = 0
읽는 칸 = 0|0|0|0|0|0  (EXACT_CERTIFIED, cap = 20)
split bound = 20  =  required = 20      배제하지 않음, 여유 0
```

즉 모형은 **정확히 빡빡**하다.  Claim 1 이 1 만큼만 부풀었다면 (`proseB` 가
바로 그 오류다) `required = 21 > 20 = bound` 가 되어 **실재하는 872 덮개를
모형이 배제**했을 것이다.  이 한 줄이 Claim 1 의 반증가능성을 보장한다.
