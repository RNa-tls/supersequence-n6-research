## 1. `H.catalogue`

   연결자가 실제로 존재할 수 있고, 모든 용량 상한이 무효가 된다.
7. **독립 감사 이력**: **있음, 두 번.**  라운드 149 정리 2.2 (518,400 쌍
   전수, 누락 0), 그리고 라운드 154 β-성분 감사에서 독립 재도출

1. **노드 ID**: `H.feas`
2. **출처**: DAG 필드는 파일이 아님 (**F2** 참조).  실제 위치:
   `r150/PROOF.md` §2 Token-Touched-Orbit Deficit Lemma (48–77 행), §3 쌍대

   선행 `r149/PROOF.md` §9.5 (460–496 행), `r149/src/feaslemma149.py`.
3. **진술** (DAG 문구): *the feasibility prune removes no realisable
   continuation*.  r150 §2 형태: 열린 비현재 궤도 중 완성 과정에서 포트를
   얻는 집합 `T` 는 `|T| <= k` (남은 토큰) 이고, 따라서 모든 완성에 대해
   `D_final >= min_{|S|<=k} sum_{q notin S, q != o} u_q =: L(U,o,k)`.
4. **직접 의존**: 없음
5. **직접 하위**: `C.chaincaps`, `C.piececaps`, `E.enumeration` (전이적 12 노드)
6. **적재 여부**: **예.**  1,101 + 220 용량 셀 **전부**와 라운드 153 등호
   증인 열거가 이 가지치기를 켜고 계산되었다.
7. **독립 감사 이력**: **있음 (전용 라운드 150).**  다만 두 감사 모두 한계를
   명시한다.  r149 §10: 가지치기를 **끄고** 재계산하는 교차검증은
   **수행 불가능** 했고 (가장 작은 셀도 120 초에 안 끝남), 두 구현이 같은
   아이디어를 공유하므로 A/B 일치가 이것을 검증하지 못한다.
   r150 §8: *"The remaining trusted component is this transparent hand theorem
   and its implementation correspondence. It is not a proof-assistant kernel
   theorem. The whole historical search was not rerun."*
8. **증명 성격**: **완전한 지필 증명 + 쌍대 증명서 + 부분 기계 확인**,
   그러나 **정리와 구현의 대응은 여전히 신뢰 성분**이다.

## 11. `H.tight`

1. **노드 ID**: `H.tight`
2. **출처**: `research/RR_L6_PROOF_145_CLAUDE.md` §9 (266–314 행),
   특히 292–300 행.
3. **진술** (DAG 문구 그대로): *at an equality row the incidence bound is
   tight, so the chain is hexagon-simple, all 120 hexagons are used, and the c
   pure circuits (complete tau-orbits) must cover the |F| = 4c unused ones*.
   §9 의 세 절: 등호 ⇒ 이분 그래프가 나무 ⇒ (a) 120 개 육각형이 전부 쓰임
   (아니면 반복 초과가 `G` 를 넘음), (b) `R_int = 0` 이라 사슬이 육각 단순,
   (c) 남은 `|F| = 120 - P = 4c` 를 `c` 개 순수 순환이 덮어야 함.
4. **직접 의존**: 없음 (수학적으로는 `H.incidence` 의 등호 조항이 가설)
5. **직접 하위**: `X.structure` (전이적 7 노드)
6. **적재 여부**: **예.**  라운드 153 공존 층 전체 —
   `X.structure -> X.exclusion -> X.nolemmaE / X.controls / X.adversarial ->
   T.ge872` — 가 오직 이 환원 위에 서 있다.
7. **독립 감사 이력**: **없음.**  라운드 153 은 이것의 **기계로 확인 가능한
   귀결** (증인마다 육각 단순, `|F| = 4c`, 모든 τ-궤도가 정확히 다섯 육각형과
   만남) 만 확인했고 (`X.structure`), **함의 자체는 재증명하지 않았다**.
8. **증명 성격**: **지필 증명이되 산문 세 줄.**  (a) 의 괄호 근거
   ("아니면 반복 초과가 `G` 를 넘는다") 는 별도 증명 대상이 없다.

## 감사 우선순위 (약한 정당화 / 큰 하위 / 숨은 완전성 가정 위험)

1. **`H.tight`** — 정당화가 가장 얇다 (산문 세 줄, 전용 감사 0).
   라운드 153 공존 층 **전부**가 이것 하나에 걸려 있고, "120 개 육각형이
   전부 쓰인다" 는 절은 근거가 괄호 한 마디뿐이라 숨은 완전성 가정 위험이
   가장 높다.
2. **`H.feas`** — 하위 12.  두 감사 라운드가 **스스로** 한계를 명시한다:
   가지치기를 끄는 교차검증은 수행 불가, A/B 일치는 같은 아이디어를
   공유하므로 무효, "정리와 구현의 대응" 이 신뢰 성분으로 남음.
   라운드 146 을 깨뜨린 결함이 정확히 이 종류였다.
3. **`H.extract`** — 하위 9.  Claim 5 가 가장 느슨하게 진술되어 있고
   (`사슬 안에서 ... R_int 이하이고`), 사슬 절단 (`sigma >= 0`,
   사슬 수 `<= d+1+h`) 에 숨은 완전성 가정 위험이 있다.
4. **`H.incidence`** — 하위 9, 그리고 `H.tight` 의 **가설**.
   DAG 출처 필드가 틀려 있어 (F1) 무엇이 감사 대상인지조차 문서에서
   바로 찾을 수 없다.  "등호 ⟺ 나무" 는 한 문장뿐이다.
5. **`H.envelope`** — 하위 9, 전용 감사 0.  (3) 의 "자르면 excess 는 줄기만
   한다" 가 한 줄 주장이다.
6. **`H.models`** — 하위 9.  표면적은 가장 크지만 **전용 감사를 가장 두껍게
   받았고** (라운드 149 전체), 남은 손 논증이 Claim 1–5 + 보조정리 1.1–1.2 로
   이미 좁혀져 있다.
7. **`H.samehex`** — 하위 9, 전용 감사 0.  다만 증명이 3 단계로 짧고
   깨끗하며 dirty 조인트를 실제로 갖는 555 개 단어에서 확인되었다.
8. **`H.master`** — 하위 9, 전용 감사 0.  항등식이라 검증이 쉽고 872 증인에서
   수치가 맞는다.  비음수성만 `H.samehex` 에 의존한다.
9. **`H.splice`** — 하위 2.  보조정리 E·F 는 두 번 재증명되었고 A–D 는
   대수적으로 짧다.
10. **`H.fixedrep`** — 하위 2.  5 개 보조정리가 짧고 검증 표본이 넓다.
11. **`H.catalogue`** — 하위 12 로 크지만 **유한 열거로 닫혀 있고 두 번
    독립 재도출** 되었다.  정당화가 가장 강한 축에 속한다.
12. **`H.wlog`** — 하위 13 으로 가장 크지만, 구조적 증명이 한 문단이고
    518,400 쌍 전수 확인이 두 번 있었다.  정당화가 가장 강하다.
