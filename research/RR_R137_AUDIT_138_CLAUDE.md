## 2. 일곱 행의 독립 재유도

우리 자신의 항등식만 쓴다: `P = 120+G`, `O = 24+k`, `D = 5O-P`, `r = O+e`,
`S = (r-1)+x-f_out`, `N = S+G-O`, `L = 844+G+S+H`, master
`L = 867+k+G+e+x+H-f_out`.

`k=3, G=2, x=H=0` 에 `L=871` 을 요구하면 master 가

    f_out = e + 1

을 **강제**한다.  그러면 `e` 에 무관하게

    P = 122,  O = 27,  D = 13,  S = 25,  N = 0,  L = 871,
    delta = (F + e) - f_out = F - 1 = 1   (F = 2)

이 따라온다.  일곱 행 `A/e0..2`, `B/e0..3` 의 `f_out` 은 각각 1,2,3,1,2,3,4 이고
Astra §1 표와 **전부 일치**한다.  그리고 보통 블록 하나(5 pass)를 떼면
`122 - 5 = 117` — 용량이 마주해야 하는 수다.

커버리지: 우리 행 표 `A/e0→M, A/e1→M|R, A/e2→R, B/e0→M, B/e1→M|R, B/e2→M|R,
B/e3→R` 는 Astra §1 의 `M-off-target` / `R-target-coupled` 열과 정확히 같고,
§6 의 네 사례 `(M,A) (M,B) (R,A) (R,B)` 가 일곱 행을 전부 덮는다.
사례 분할이 `e` 에 의존하지 않는다는 점도 §6 의 서술과 일치한다.

## 3. 10,800 개 위치 항등식

짧은 pass `(v,a)` 의 끝점 `y = sigma^(a-1)(v)`, 다음 진입 `c = sigma(y)`.
표적은 `y3 y4 y5` 뒤에 `(y0,y1,y2)` 의 꼬리 배열.  720 단어 × 5 길이 × 3 꼬리
= **10,800** 전수 확인, 예외 **0**:

* `120` 표적은 `c` 와 **같은** 궤도이고 정확히 `tau^2(c)`;
* `201`, `210` 은 `c` 와 **다른** 궤도;
* `a < 6` 이면 셋 다 `orb(v)` 와 다르다;
* 값-정규화 `c = 012345` 에서 표적은 `234015 / 234150 / 234105` — Astra §2 와 일치.

full source pass 통제도 재현: `120` 만 `orb(v)` 에 남고(720/720) `201`/`210` 은
바깥(720/720).  이것은 나 자신의 이전 라운드 결론 "M-off-target ⟺ M3b/M3c" 와
같은 사실의 다른 표기다 (`120 = M3a`, `201 = M3b`, `210 = M3c`).

## 5. 발견하고 닫은 구멍 — 경량 연결자는 정확히 둘

사슬 모형(`C0`, `R`)은 궤도를 바꾸는 연결자로 `201` 과 `210` **둘만** 쓴다.
그런데 끝점에서 나가는 weight-3 꼬리는 여섯 개이고, 그중 `021` 과 `102` 는
**다른 육각형·다른 궤도**다.  이것들이 합법이라면 모형은 상계가 아니게 되고
§7 의 용량 모순 **전체가 무너진다**.

닫는 것은 라운드 126 의 **조인트 합법성 기준**이다: `omega = m` 전이는 그
`m-1` 개 중간 창 가운데 순열이 하나도 없을 때에만 합법.  전수 확인 결과:

| 꼬리 | 720 중 합법 | 성질 |
|---|---:|---|
| `w2/(0,1)` | **0** | 중간 창 `y1..y5 y0` 가 순열 |
| `w2/(1,0)` = `tau` | **720** | 같은 궤도, 위상 +1 |
| `w3/012` | **0** | `t3 = y0` → 중간 창이 순열 (게다가 같은 육각형) |
| `w3/021` | **0** | `t3 = y0` → 중간 창이 순열 |
| `w3/102` | **0** | `{t3,t4} = {y0,y1}` → 둘째 중간 창이 순열 |
| `w3/120` | **720** | 같은 궤도, 위상 **+2** |
| `w3/201` | **720** | 궤도 밖 |
| `w3/210` | **720** | 궤도 밖 |

부분 합법 꼬리는 **하나도 없다**(전부 0/720 또는 720/720).  라운드 126 카탈로그
`{w2: 1, w3: 3}` 와 일치.  따라서 run 연장은 `tau` 뿐, 궤도 전환은 `201`/`210`
뿐이고 **두-연결자 모형은 건전한 상계**다.

이와 함께 자원 계수가 모형을 강제한다: `S` 는 유료 조인트 수이므로 궤도 `m` 개에
run `m` 개면 전환에 이미 `m-1` 개가 쓰인다.  §5 의 `S_in = m-1` (M) 은 여분이
없다는 뜻이라 궤도 안 유료 건너뛰기(`120`, 위상 +2)가 **하나도** 없고,
`S_in = m` (R) 은 정확히 하나의 여분 — 예외적 root 반환 — 만 허용한다.

또한 720 개 **값-재명명이 전부 사슬 모형의 자기동형**임을 전수 확인했다
(위반 0, 단어 위에 추이적).  `orbph` 는 임의 기준점 기반이라 궤도별 상수 위상
이동을 허용해야 하며(696 개가 이동을 갖는다), 모형은 "그 궤도의 어느 다섯 자리를
썼는가" 만 보므로 무해하다.  이로써 `v = 012345` 정규화가 정당화된다.

## 7. 하중을 지는 단 하나의 단계 — 사밀성

§6 의 포함 논증이 요구하는 것은: 추출 구간 안에서 열린 궤도가 **전부 사밀**하다는
것, 즉 바깥에 남는 궤도와 서로소라는 것.  Astra 는 이것을 손 증명으로 처리하고
스스로 그렇게 표시했다:

* 검증기 선언: `mathematical_scope = 'finite controls and local capacity complete;
  universal gap inclusion is the separate hand proof'`;
* `rr_round137_gap_cut_codex.json` 의 `scope`: `'preserved finite controls;
  not a universal proof'`;
* 원장의 `proof_layers`: `universal_inclusion: 'HAND_PROOF, sections 5-6;
  not certified by samples'`.

**이 전제가 얼마나 하중을 받는가 — 정량화.**  궤도 `s` 개가 두 조각에 걸치면
pass 총합은 여전히 117 이지만 `O_in + O_out = 26 + s` 이므로

    D_in + D_out = 5(26+s) - 117 = 13 + 5s

즉 **공유 궤도 하나당 결손 예산이 5 늘어난다**.  그러면

| 공유 궤도 `s` | 결손 예산 | M 최대 | 117 미만? | R 최대 | 117 미만? |
|---:|---:|---:|---|---:|---|
| 0 | 13 | 112 | **예** | 103 | **예** |
| 1 | 18 | **≥ 132** | **아니오** | ≥ 107 | 예 (하한) |

**공유 궤도가 단 하나만 있어도 M 용량 모순은 사라진다.**  (`s=1` 값은 `d ≤ 13`
조합만 쓴 하한이므로 실제 최대는 더 크다.)  그러므로 §6 은 편의가 아니라 폐쇄
전체를 떠받치는 단계이고, 감사에서 그것을 독립적으로 확립하지 못한 이상
CONFIRMED 를 줄 수 없다.

**확인된 것**: Astra 의 유한 영역에서는 사밀성이 성립한다.  나는 **835 개 컨트롤을
내 기하로 완전히 독립 재현**했다(Astra 의 JSON 은 데이터로만 읽고 코드는 쓰지 않음).
`53` 개 n=4 M, `268` 개 n=6 M, `514` 개 n=6 R.  각 행마다 문자 단어에서 창·pass·
조인트 무게·궤도를 다시 만들어 검사:

* 두 조각 모두 문자 무반복;
* **두 조각의 궤도 집합이 서로소 (사밀성)** — 835/835 성립;
* 기록된 `P, O, D, r, e, S, H, windows` 가 내 재계산과 일치;
* 기록된 조인트 무게가 일치;
* 모든 pass 가 full;
* M 조각은 반복 궤도 없음 · `e = 0`; R 조각은 정확히 **하나**의 두 겹 궤도이고
  그것이 **첫 run 이자 마지막 run** · `e = 1`;
* heavy 조인트 없음, 결손 비음수.

**실패 0건.**  그러나 이것은 **명시된 유한 영역**이지 보편 증명이 아니다.

## 8. 인증서·계보 — 결함 하나 (수학과 무관)

**Astra 자신의 검증기 `src/verify_round137_gap_capacity_codex.py` 는 감사 커밋에서
`AssertionError` 로 실패한다.**  원인은 정확히 한 줄:

    for f,value in c['source_sha256'].items(): assert sha(ROOT/f)==value

용량 인증서 `rr_round137_root_return_capacity_codex.json` 이 기록한
`src/chain_capacity_115.c` 의 SHA256 은 `c7694b66f3d31770...` 인데 커밋된 파일은
`2287c05efdfe0cb5...` 다.  그런데 이 파일은 **라운드 115(`c4291f6`) 이후 한 번도
바뀌지 않았고** `026eb61`, `2b9dcf0`, `ec8a5f1` 에서 모두 동일하다.  더구나
`c7694b66...` 는 저장소의 **객체 데이터베이스 전체와 작업 트리 어디에도 없다**
(모든 브랜치의 모든 블롭을 훑어 확인).  즉 인증서는 이 저장소에 커밋된 적 없는
