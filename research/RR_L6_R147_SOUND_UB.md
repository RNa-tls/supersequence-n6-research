# 라운드 147 — 건전한 가지치기 상한의 정의와 증명

라운드 146 이 찾은 결함: 사슬 탐색기는 가지치기 표를 **남은 예산의 합**으로
조회하는데(`left = (AMAX-au)+(BMAX-bu)+(EMAX-eu)`), 생성기는 **분할마다** 한 줄을
그 합 키 아래로 내보내고 C 로더는 같은 키의 **최솟값**을 택했다.  합 키의 값은
그 합을 갖는 **모든** 분할을 지배해야 하는데 최솟값은 그 반대다.  전말:
`research/ERRATA_146_CHAIN_UB.md`.

라운드 147 은 **집계 자체를 없앴다** (지시서의 OPTION A).

---

## 1. 새 표의 정의

    UB[tok][d][a_left][bb_left][e_left][h_left]

탐색기(`r147/src/l6_chain_capacity_147.c`)는 상태 `q` 에서 **정확히 그 벡터로**
조회한다:

```c
int reach = ports + ubound(tok, DMAX - deficit + 4 + 5 * tok,
                           AMAX - au, BMAX - bu, EMAX - eu, HMAX - hu) - 1;
```

합으로 뭉치는 자리가 없으므로 "지배하는 최댓값" 논증이 필요하지 않다.  건전성은
한 문장으로 줄어든다: **키에 저장된 값이 그 예산 벡터를 갖는 사슬의 포트 수
상한이어야 한다.**

생성기(`r147/src/ub147.py`)는 모든 키에 대해

    UB[K] = min( 120 + a + bb + e ,
                 min { cap(K') : K' 는 검증된 셀, K' >= K 성분별 } )

을 쓴다.  `cap(K)` 는 예산 벡터 `K = (b, d, a, bb, e, h)` 를 갖는 사슬의 참
용량(최대 포트 수)이다.

## 2. 두 개의 증명된 사실

### (P1) 예산 단조성.  `K <= K'` (성분별) 이면 `cap(K) <= cap(K')`.

탐색기의 모든 예산은 **상한**이며 요구가 아니다.  소스에서 각 예산이 쓰이는
자리는 정확히 다음 뿐이다:

| 예산 | 코드에서의 사용 | 의미 |
|---|---|---|
| `tok` | `if (cost > tok) return;` | 토큰이 많으면 허용되는 이동이 더 많다 |
| `DMAX` | `if (deficit <= DMAX) { 기록 }`, `feas()` 의 `tot <= DMAX` | 결손 예산이 크면 더 많은 사슬이 기록된다 |
| `AMAX` | `if (au < AMAX) step(dirtyA...)` | |
| `BMAX` | `if (bu < BMAX) step(dirtyB...)` | |
| `EMAX` | `if (eu >= EMAX) return;` | |
| `HMAX` | `if (hu + heavycost <= HMAX) step(heavy...)` | |

어떤 예산도 "정확히 이만큼 써야 한다"는 형태로 쓰이지 않는다.  그러므로 `K` 에서
허용되는 모든 사슬은 `K'` 에서도 허용된다.  허용 집합이 커지면 그 위의 최댓값은
줄어들 수 없다. ∎

(`DMAX` 만 주의가 필요하다: `feas()` 의 가지치기가 `DMAX` 를 쓰지만 그것도
`tot <= DMAX` 형태의 필요조건이므로 `DMAX` 가 커지면 통과하는 상태가 늘어난다.
기록 조건 `deficit <= DMAX` 도 같다.)

### (P2) 육각형 계수.  `cap(K) <= 120 + a + bb + e`.

사슬의 각 포트는 회전 육각형 하나에 떨어진다.  이미 이 사슬이 쓴 육각형에
떨어지는 포트는 `step()` 에서 다음 셋 중 하나여야 한다:

* 타입 A dirty edge — `hexid[dirtyA[v]] == hexid[v]` 가 `geometry()` 에서
  단정되고, 예산 `a` 를 한 단위 쓴다;
* 타입 B dirty edge — 같은 단정, 예산 `bb` 를 한 단위;
* 보통 충돌 — `if (!newhex && isdirty <= 0) { if (eu >= EMAX) return; spend_e = 1; }`,
  예산 `e` 를 한 단위.

그 밖의 경우 `step()` 은 새 육각형을 표시하고 `hexcount` 를 올린다.  따라서

    #포트 <= #서로 다른 육각형 + (a + bb + e 사용량) <= 120 + a + bb + e. ∎

(이 부등식은 탐색기 자신의 표 없는 prune `reach2 = ports + (NH - hexcount) + left`
가 쓰는 것과 같은 것이다.)

## 3. 건전성

`UB[K]` 는 두 값의 최솟값이다.

* `120 + a + bb + e >= cap(K)` — (P2).
* 각 `cap(K')`, `K' >= K` 에 대해 `cap(K') >= cap(K)` — (P1).

유한 개의 유효한 상한들의 최솟값은 여전히 상한이므로 `UB[K] >= cap(K)`. ∎

**순환 없음.**  `cap(K')` 는 **검증된** 셀의 값만 쓴다.  검증된 셀이란 실행이
`capped = false` 로 끝난 정확한 용량이며, 그 실행이 쓴 표는 (i) 표 없음이거나
(ii) 더 앞서 검증된 셀들로만 만들어진 표다.  생성기는 대상 셀을 자기 표에서
명시적으로 제외한다(`exclude={cell}`).  그러므로 귀납에 순환이 없다.

**단조성.**  `K1 <= K2` 이면 `{K' >= K2} ⊆ {K' >= K1}` 이므로 안쪽 최솟값은
비감소이고, `120+a+bb+e` 도 비감소다.  비감소 함수 두 개의 최솟값은 비감소.
따라서 생성된 표는 C 로더가 요구하는 단조성을 자동으로 만족한다 — 로더는 그것을
**검사만** 하고 절대 스스로 고치지 않는다 (이웃 값으로 올리는 그 조작이 라운드
144 에서 건전한 파일을 무효로 만든 연산이다).

## 4. 표가 말하지 않는 자리

키가 검증된 셀에 지배되지 않으면 값은 `120 + a + bb + e` 가 된다 — 유효하지만
약하다.  표를 아예 주지 않은 실행에서도 `ubound` 는 이 값을 돌려준다:

```c
SAFEUB = 120 + AMAX + BMAX + EMAX;
```

라운드 144 는 이 자리에 **상수 120** 을 썼다.  재사용 예산이 양수일 때 120 은
상한이 아니다.  그 결과 `target > 120` 인 결정형 실행은 루트에서
`reach = 1 + 120 - 1 = 120 < target` 으로 가지쳐져 **통째로 공허**해졌다.
라운드 146 의 재검증에서 셀 `2|8|2|0|0` 이 실제로 그랬다: 노드 **1 개**로
"CC <= 121" 을 주장했다.  그 항목은 무효이며 라운드 147 에서 다시 계산한다.

## 5. 독립 검증기

`r147/src/ub147.py::validate_table` 는 같은 표를 **접미 최솟값 전파가 아니라**
쌍별 지배 무차별 대입으로 다시 계산해 모든 항목을 비교한다.  그 밖에 파일
자체를 검사한다: 매직 `UB7 <count>`, 정확히 7 열, 개수 일치(절단·패딩 탐지),
인덱스·값 범위, 값이 충돌하는 중복 키, 조회 가능한 키의 누락·초과, 단조성.
`recompute147.py` 는 검증을 통과하지 못한 표로는 탐색기를 **실행하지 않는다**.

C 쪽 로더도 같은 것을 독립적으로 다시 검사하고 하나라도 어긋나면 `exit 3` 한다.
`r147/src/failclosed147.py` 가 16 가지 고장(잘못된 매직, arity 5/3, 절단, 패딩,
충돌 중복 키, 범위 밖 인덱스·값, 깨진 행, 단조성 위반, 라운드 144 파일 원본 2 종,
없는 파일)을 먹여 전부 거부됨을 확인한다 — 16/16.
