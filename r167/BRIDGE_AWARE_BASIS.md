# 라운드 167 — 다리를 고려한 2차 경로 기저 재최적화

**증명 상태**: 이 문서의 모든 결과는 *증명서 계획*에 관한 것이다.
`L6 >= 872` 도, `L6 = 872` 도 여기서 증명되지 않는다.  소진 주장도 없다.
바뀐 것은 **census 가 소비하는 상한들을 기계 독립적으로 다시 세우는 데
필요한 증명서의 최소 개수**다.

## 1. 규칙 체계 — 무엇이 새로 허용되는가

라운드 166 의 걷기 집합 논증에서 두 규칙이 나온다.  **수치 일치가 근거가
아니다.**  근거는 a = bb = e = h = 0 에서 사슬 목록이 조각 모형의 수를
정확히 허용한다는 사실(720/720 출처에서 확인)과, 토큰·적자 부과가 동일하고,
마스크는 *수용 조건*이라 걷기를 없앨 뿐이라는 것이다.

```
(BRIDGE-LE)   cap_piece(b, d, fp, lp)  <=  cap_chain(b, d, 0, 0, 0, 0)
(BRIDGE-EQ)   cap_piece(b, d, 0,  0 )   =  cap_chain(b, d, 0, 0, 0, 0)
```

(BRIDGE-EQ) 는 fp = lp = 0 에서 두 걷기 집합이 **같기** 때문에 성립한다.
이것이 이번 라운드에서 실제로 쓰인 새 규칙이다.  수치 확인(46/46 일치)은
**증명이 아니라 보강 증거**로만 기록한다.

여기서 세 가지가 따라온다.

1. **증명서 우주는 사슬 셀 집합이다.**  이 저장소에 존재하는 기계 독립적
   2차 경로는 사슬 모형 소진 트리(`L6-EXTREE-*`) 하나뿐이고 조각 모형
   소진 생성기는 없다.  마스크가 걸린 조각 값은 (BRIDGE-LE) 로만 지탱된다.
2. **이미 이중 경로인 조각 값이 사슬 값을 공짜로 준다.**  (BRIDGE-EQ) 는
   양방향이므로 유지된 `(b,d,0,0)` 조각 값은 `(b,d,0,0,0,0)` 사슬 값을
   증명서 없이 준다.
3. **공짜 수입이 행을 하나 닫는다.**  라운드 165 가 노출된 행으로 센 181
   중 한 행(L871, `k=4, G=1, c=1`, 나머지 0)이 이 공짜 수입만으로 다시
   닫힌다.  그래서 이번 라운드의 목표 행 수는 **180** 이다.

## 2. 다리 후보의 완전 열거 — 18 이 아니라 29

라운드 166 은 **라운드-152 표에 이미 있는 사슬 셀만** 다리로 인정했다.
표에 없는 셀도 정의는 멀쩡하고 증명서를 바로 생성할 수 있다 — 라운드 166
스스로 "증명서 순서 접두사는 허구"임을 보였기 때문에 선행 셀이 필요 없다.

109 개 조각 사실을 `(b,d)` 로 묶으면 **29 개 그룹**이 나오고 이것이 전부다.
완전성 논증: 조각 사실 `(b,d,fp,lp)` 를 묶는 사슬 셀 `K'` 는 반드시
`(b,d,0,0,0,0)` 을 성분별로 지배해야 하고, 단조성에서
`cap_chain(b,d,0,0,0,0) <= cap_chain(K')` 이므로 `(b,d)` 셀이 가장 강한
다리다.  따라서 `(b,d)` 로 묶는 것이 곧 완전 열거다.

라운드 166 이 놓친 11 개가 여기서 복구된다.

## 3. 두 목적 — 사실 수준(A) 대 행 수준(B)

* **A**: 옛 288 개 사실 전부에 (약해질 수 있는) 증명된 상한을 붙인다.
* **B**: 노출된 census 행 180 개를 전부 다시 **엄격히 닫는다**.

B 가 진짜 요구 조건이다.  A 는 B 를 **자동으로 함의하지 않는다** — 마스크가
걸린 조각 사실은 원래 표 값보다 **느슨한** 다리 값으로만 지탱되므로, A 를
만족해도 행이 열릴 수 있다.  그래서 A 의 해가 B 를 만족하는지 **가정하지
않고 계산해서 확인**했다.

결과: **A 와 B 의 해가 집합으로 완전히 일치한다** (190 개, 차집합 양쪽 모두
공집합).  A 의 소박한 계수 193 에서 3 이 빠지는데, `0|15`, `0|18`, `0|19`
(모두 `|0|0|0|0`) 는 유지된 이중 경로 조각 값에서 공짜로 나오기 때문이다.

## 4. 증명서 우주는 계산으로 확정했다

"후보를 어디까지 볼 것인가"를 추측하지 않았다.  `CC`/`PC` 를 계측해서
노출된 행을 평가할 때 census 가 실제로 조회하는 셀을 전부 기록했다.

| | 개수 |
|---|---:|
| 조회되는 사슬 셀 | **571** |
| 그 중 라운드-152 표에 있는 셀 | 562 |
| 표에 없고 (BRIDGE-EQ) 로 값이 예측되는 셀 | 9 |
| 값을 전혀 모르는 셀 | **0** |
| 조회되는 조각 셀 | 220 (조각 표 전부) |

**census 가 조회하지 않는 셀의 증명서는 어떤 경계도 바꾸지 못한다.**  따라서
571 개가 완전한 후보 모집단이고, 값을 모르는 셀이 하나도 없으므로 아래의
하한은 "내가 본 범위 안에서"가 아니라 진짜 하한이다.

여기서 이미 무료로 얻어지는 셀과 값이 해석적 대체값(`120 + a + bb + e`)
이상이라 쓸모없는 셀을 빼면 **증명서 우주는 222 개**다.

## 5. 최소해와 일치하는 하한

방법은 라운드 165 와 같되 방향이 반대다 — 하나씩 빼는 대신 하나씩 준다.

1. **우주 전체가 실현 가능**: 222 개를 다 주면 180 행이 전부 닫힌다.
2. **개별 필요성**: 222 개 각각에 대해 `U \ {K}` 를 평가했다.  **190 개**는
   행을 연다(필요), **32 개**는 열지 않는다(불필요).
3. **필요 집합만으로 충분**: 190 개만 주어도 180 행이 전부 닫힌다.

닫힘은 주어진 집합에 대해 **단조**이므로(증명서는 경계를 낮추기만 한다),
`U \ {K}` 가 행을 열면 `K` 를 빼는 **모든** 실현 가능 부분집합도 그 행을
연다.  따라서 190 은 하한이고 동시에 상한이다 — **최소이며 유일**하다.

유일성은 개수 최소보다 강하다.  최적해가 *모든* 실현 가능 집합에 포함되므로
**개수·노드 수·저장 공간 등 단조 비용 전부를 동시에 최소화**한다.  가중
문제 세 개(§8)는 따로 풀 필요가 없다.

### 최적해의 구조

```
190 = 라운드 165 의 사슬 사실 179 개 (하나도 빠지지 않는다)
    + 다리 셀 11 개:  0|20  1|13  1|14  1|15  2|8  2|9  2|10
                      3|3   3|4   3|5   4|0        (모두 |0|0|0|0)
```

그 11 개 중 8 개는 라운드-152 사슬 표에 없어 값이 (BRIDGE-EQ) 로 예측된
셀이고, 3 개(`1|13`, `2|8`, `3|3`)는 표에는 있으나 라운드 165 의 사슬
기저에는 없던 셀이다.  **사용자 지시대로 옛 179 기저 밖의 셀도 후보로
열어 둔 것이 바로 이 11 개를 찾아낸 이유다.**

다시 조립한다.  **10 초**에 끝난다(해법기 100 초, 평가량 기준 210 배 절약).

읽기는 위의 공유 트리 사실 때문에 성립하지 않는다.  이것도 정정해 둔다.

## 10. 민감도 — 예측 값이 틀리면 어디서 깨지는가

최적해 190 개 각각에 대해, 그 셀의 값이 얼마나 커져도 180 행이 계속 닫히는지
이분 탐색으로 구했다.  값을 올리는 것은 "증명서를 빼는 것"과 "그대로 두는
것" 사이에 있으므로, 영향을 받을 수 있는 행은 **그 셀을 완전히 뺐을 때
열리는 행**뿐이다(단조성).  그래서 셀당 행 1~20 개만 보면 된다.

* **여유가 0 인 셀은 하나도 없다.**
* (BRIDGE-EQ) 로 값을 **예측한** 8 개의 여유:

| 셀 | 계획 값 | 안전 상한 | 여유 |
|---|---:|---:|---:|
| `4\|0\|0\|0\|0\|0` | 80 | 119 | 39 |
| `3\|5\|0\|0\|0\|0` | 91 | 119 | 28 |
| `3\|4\|0\|0\|0\|0` | 91 | 115 | 24 |
| `2\|10\|0\|0\|0\|0` | 100 | 119 | 19 |
| `2\|9\|0\|0\|0\|0` | 96 | 115 | 19 |
| `0\|20\|0\|0\|0\|0` | 106 | 119 | 13 |
| `1\|15\|0\|0\|0\|0` | 106 | 119 | 13 |
| `1\|14\|0\|0\|0\|0` | 106 | 115 | 9 |

**예측은 계획 입력이지 증명 단계가 아니다.**  생성된 증명서가 위 "안전
상한"을 넘는 값을 보고하면 그 셀의 계획은 반증된 것이고, 진짜 값으로 행
최적화를 다시 돌려야 한다.

## 11. 검증기 A 의 한계를 없앴다 (라운드 166 §10)

라운드 166 은 배치 3 에 검증기 A 를 돌리지 못했다.  원인은 **검증 논리가
아니라 드라이버**였다: `extree152.py` 의 `main()` 이 토큰 전체를 리스트로
올리는데 평탄화하면 1.64 억 토큰이다.

`extree152.Validator.validate` 는 토큰 열을 `len()` 과 **단조 증가 인덱스**
로만 건드린다.  그래서 압축 해제 스트림 위의 창(window) 뷰를 리스트 대신
넘기면 그대로 동작하고 메모리는 O(토큰) 에서 O(창) 으로 바뀐다.

`r152/src/extree152.py` 는 **한 바이트도 고치지 않았다** — 독립 구현이라는
성질과 해시 고정을 유지해야 하기 때문이다.  새 드라이버
(`r167/src/verifyA167.py`)는 L6-EXTREE-2 의 `ref` 줄도 해석해 참조 배치를
먼저 해시 검사·검증하고 그 셀들로 (p) 정당화 표를 초기화한다.

**결과 — 세 배치 전부 검증기 A 를 통과했다.**

| 배치 | 셀 | 노드 | 검증기 A |
|---|---:|---:|---|
| `r164/certs/extree_prefix_164.txt.gz` | 51 | 7,254,695 | 통과 |
| `r166/certs/extree_batch2_166.txt.gz` | 17 | 20,309,922 | 통과 |
| `r166/certs/extree_batch3_166.txt.gz` | 7 | 136,442,163 | **통과** |
| 합 | **75** | **164,006,780** | `all_ok` |

셀별 노드 수는 검증기 B 가 잰 값과 **정확히 일치**한다.  라운드 166 §10 의
첫 번째 한계는 이제 없다 — 배치 3 도 **검증기 둘**을 모두 통과한다.

### 처음 작성한 드라이버는 틀렸고, 검증기 A 가 잡아냈다

첫 실행에서 배치 3 의 첫 셀 `1|6|0|0|0|0` 이
`unjustified leaf at token 78: ports=45 deficit=10 r1=120 r2=79` 로
거부되었다.  원인은 **증명서가 아니라 내 드라이버**였다: 배치가 다른 배치를
참조하면 (p) 정당화 표는 참조 배치의 **추이적 폐쇄**를 물려받아야 하는데,
참조 배치가 스스로 쓴 셀만 돌려주어 배치 3 이 배치 1 의 51 개 셀을 보지
못했다.  `r2 = 79` 가 `cap+1 = 65` 보다 커서 (p) 가 성립하지 않은 것이
정확히 그 증상이다.  고친 뒤 전부 통과했다.  실패한 실행의 보고서는
저장소에 커밋하지 않고 기록으로만 남긴다 — 잘못된 산출물을 고정하지
않는다는 규칙 때문이다.

## 12. gzip 규칙을 형식화했다

라운드 166 은 "다른 경로로 생성하면 컨테이너 바이트가 다르다"를 성질로만
적었다.  원인은 정확히 이것이다:

```python
gzip.GzipFile(fileobj=raw, mtime=0)   # filename 을 주지 않으면
                                      # GzipFile 이 fileobj.name 으로 대체한다
```

그래서 출력 경로가 gzip **FNAME 헤더**에 들어간다.  `mtime=0` 은 다른
비결정성만 없앤다.  실제로 기존 세 배치의 FNAME 은 각각
`extree_prefix_164.txt`, `extree_batch2_166.txt`, `extree_batch3_166.txt` 다.

두 규칙을 세운다.

* **(G1) 해시로 고정되는 증명 객체는 정본 평문이다.**  매니페스트는
  `sha256` 옆에 `plain_sha256` 을 함께 적는다.  검증기는 평문을 읽으므로
  증명 하중은 `plain_sha256` 이 지고 컨테이너 해시는 출처 정보일 뿐이다.
* **(G2) 압축 산출물은 `filename=""` 로 쓴다.**  컨테이너가 본문만의 함수가
  되어 경로와 무관하게 재현된다.  `r167/src/gzrule167.py:write_gz` 가 이를
  구현하고, 같은 본문을 두 경로에 써서 바이트가 같음을 시연한다.

기존 라운드 164·166 산출물은 **다시 쓰지 않는다.**  컨테이너 해시가 이미
감사된 매니페스트에 고정되어 있고, 다시 쓰면 이미 수행·검사된 재현 주장이
무효가 된다.  대신 `plain_sha256` 으로 **다시 고정**했고, 새 규칙은 라운드
168 이후 생성물에 적용한다.

## 14. 라운드 168 생성 계획

**값싼 것부터** 생성한다.  계획 값이 틀렸다면 몇 주가 아니라 몇 분 만에
드러나야 하기 때문이다.  각 체크포인트는 **그 시점에 닫혀 있어야 할 행 수를
미리 못박는다.**  못 맞추면 지연이 아니라 반증이다.

| 체크포인트 | 증명서 | 누적 탐색 노드 | 계획 EXTREE 노드 | 닫혀야 할 행 | 남은 행 |
|---|---:|---:|---:|---:|---:|
| 25 % | 167 | 21,229,676,590 | 24,051,100,608 | **167** | 13 |
| 50 % | 176 | 41,648,002,234 | 47,183,021,730 | **174** | 6 |
| 75 % | 180 | 62,462,648,281 | 70,763,934,237 | **178** | 2 |
| 100 % | 182 | 82,880,902,926 | 93,895,774,924 | **180** | 0 |

비용이 극단적으로 꼬리에 몰려 있다: **182 개 중 167 개가 전체 예산의 25 %
안에 들어가고 행 180 개 중 167 개를 닫는다.**  마지막 15 개가 나머지 75 %
를 쓴다.  가장 비싼 다섯은 `2|10|0|0|0|0`, `2|8|2|0|0|0`, `2|7|2|0|0|0`,
`2|5|0|0|0|1`, `2|9|0|0|0|0` 이다.

## 15. 하지 않은 것

* **대규모 증명서를 생성하지 않았다.**  사용자 지시대로 최소화가 끝나기

  동일성이다.

  일치시켰다.
* **소진이나 `L6 >= 872` 를 주장하지 않았다.**
