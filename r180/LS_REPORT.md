## 1. LS의 정확한 진술 (감사)

R179 §7의 진술은 다음과 같습니다.

> **LS(n; A, c):** 모든 g ≥ 0에 대해 `M_n(g) ≤ A + c·g`, c ≥ 1.

`M_n(g)`는 R176 §1의 정의로, 총 charge ≤ g인 **모든 `ModelTrail`**(marked 포함)의 최대 row 수입니다.

- **대상 g:** 모든 g. Bridge 인스턴스의 각 trail charge cᵢ는 0..u의 임의 값일 수 있으므로, `ls_core`의 가정 `hinst`는 모든 g에서의 상한을 소비합니다.
- **대상 trail:** 모든 `ModelTrail`. route에서 나왔는지, payload를 만족하는지는 요구하지 않습니다.
- **정정 형태:**
  - **LS₍≥g₀₎(n; A, c):** ∀ g ≥ g₀, `M_n(g) ≤ A + c·g`.
  - 이 경우 g < g₀는 C1으로 처리해야 합니다. 두 영역을 합치면 전역 아핀 상한 `M_n(g) ≤ A′ + c·g`, `A′ = max(A, (n−2) + ((n−3)/2 − c)(g₀−1))`가 됩니다(c ≤ (n−3)/2일 때).
  - 따라서 `ls_core`는 A 대신 **A′**로만 적용됩니다(§6).

## 2. 작은 charge의 장애물

- `M_n(0) = n−2`, `M_n(2) = 2n−5`이므로 `A + 2c ≥ 2n−5`입니다. A = n−2이면 c ≥ (n−3)/2가 강제됩니다(R179와 같음).
- A를 O(n)으로 키우면 g = 2의 장애물은 사라집니다(A = 2n이면 c ≥ 0이면 충분).
- 그러나 **새 장애물**이 생깁니다. 정리 W의 walk는 g = Θ(n)에서 row Θ(n²)를 가지므로 **A = O(n)이 불가능**합니다(§3).

## 3. 명시적 반례족 (정리 W)

**special-cₙ walk.**
- 모든 row의 special 기호가 cₙ이고, 각 row는 full(길이 n−1) 또는 T(길이 n−3, charge 2, 생략 없음)입니다.
- full row 다음 start는 φ(p)이고, T row 다음 start는 R176의 출구 `D+wvz`입니다: `tm(s) = (s_{n−2}, s₀, …, s_{n−5}, s_{n−3}, s_{n−4}, s_{n−1})` (0-기반).
- 모든 row의 special이 같으므로 Lemma U에 의해 **ModelTrail ⇔ 모든 순환 단어 W가 서로 다름**입니다.
- 호환성은 R174 정리 2(a)와 R176 4.2(c)가 보장합니다.

**정리 W (모든 n ≥ 7).** 항등 start에서 시작해 "T row 하나 + full row n−4개"를 한 주기로 K = ⌊(n−3)/3⌋ 주기 반복하고, 끝에 full row 하나를 더합니다. 이 trail은 row `(n−3)K + 1`개, charge `2K`인 `ModelTrail`입니다. 그 접두부들을 취하면 0 ≤ J ≤ K 모든 J에 대해 `M_n(2J) ≥ (n−3)J + 1`입니다.

*증명.* N = n−1, W_j = j번째 T row의 순환 단어, 그리고 `W₀`의 위치를 절대 좌표로 씁니다.

1. **한 주기의 합성 위치 사상.** `φ^{n−4}∘tm`을 계산하면 `(s_{n−5}, s_{n−3}, s_{n−2}, s₀, …, s_{n−6}, s_{n−4}, s_{n−1})`입니다.
   - 순환 단어로 보면 **인접 전치 하나**입니다: `W_{j+1} = W_j`에서 위치 `c_j, c_j+1`의 글자를 교환.
   - 교환 위치는 `c_j = c₀ − 3j (mod N)`, `c₀ = n−5`입니다.
   - 주기 j의 이동 글자는 `x_j = W_j[c_j + 1]`이고 cursor(= start의 위치 n−2 글자)입니다.
2. **틀.** 주기 j의 row들은 틀 `(E_j = W_j∖x_j, x_j)`의 **서로 다른 n−3개 틈**을 차지합니다.
   - T row는 원래 틈에 있습니다. `tm` 뒤 full row들은 x_j가 한 칸씩 전진한 틈입니다.
   - 쓰이지 않은 유일한 틈의 단어가 `W_{j+1}`입니다.
3. **교환 위치의 서로소 (j < K).** 0 < 3(j−i) ≤ 3(K−1) ≤ N−5이므로 `c_j ≢ c_i, c_i ± 1`입니다.
   - 따라서 교환들은 서로소인, 아직 건드리지 않은 위치에 작용합니다.
   - 그러므로 `x_j = W₀[c₀+1−3j]`이고, 교환 k의 두 글자 `W₀[c_k], W₀[c_k+1]`는 모두 서로 다릅니다.
4. **j − i ≥ 2이면 틀 i, j는 단어를 공유하지 않습니다.**
   - 공유하려면 `W_i∖{x_i,x_j} = W_j∖{x_i,x_j}`(순환 단어)여야 합니다(Lemma U).
   - 그런데 교환 i+1의 두 글자(x_i, x_j가 아님)는 W_i에서 "u 바로 다음 v", W_j에서 "v 바로 다음 u"입니다. x들을 지워도 인접이 유지되고, 길이 n−3 ≥ 4이므로 두 순환 단어는 다릅니다.
5. **j = i+1이면 틀 i, j는 `W_{i+1}` 하나만 공유합니다.**
   - `W_{i+1}`에서 `x_i`는 위치 `c_i`, `x_{i+1}`은 위치 `c_i − 2`에 있어 인접하지 않습니다. 따라서 Lemma U의 다른 틈 경우이고 공통 단어는 하나입니다.
   - `W_{i+1}`은 주기 i에서 쓰이지 않으므로 중복이 없습니다.
6. **끝.** 주기 안의 단어는 서로 다른 틈이므로 다릅니다. 마지막 full row는 `W_K`(틀 K−1의 빈 틈)입니다.
   - 따라서 모든 단어가 다르고, trail은 `ModelTrail`입니다.
   - row 수는 (n−3)K + 1, charge는 2K입니다. ∎

**검증 (`family180.py`).**
- 주장 S1–S5(row 수, 교환 위치 공식 `c_j`, `x_j`, 틀 소속, 단어 서로 다름)를 n = 7..30에서 확인했습니다.
- 검증기 B로 n ≤ 30 전부, 검증기 A로 n ≤ 14를 통과했습니다(`certs/family180.json`).

**따름정리 (전역 LS의 반증).** 정리 W와 C1을 합치면 `(n−3)J + 1 ≤ M_n(2J) ≤ (n−2) + (n−3)J` (0 ≤ J ≤ K)입니다.
- LS(n; A, c)가 참이면 `A ≥ (n−3−2c)K + 1`입니다.
- c = O(1)이면 A ≥ (n − O(1))·⌊(n−3)/3⌋ = Θ(n²)이므로, **A = O(n), c = O(1)은 불가능**합니다(n이 충분히 크면).
- 더 일반적으로 A = o(n²)와 c = o(n)도 함께 성립할 수 없습니다.

**경험적 연장 (`growth180.py`, n = 8..50, 관찰일 뿐 증명 아님).**
- 같은 주기 walk는 정확히 다음 주기 수만큼 유효하고, 모든 경우 row = (n−3)J입니다.
  - n ≡ 2 (mod 3): `J(n) = T_{2(n−2)/3}`
  - n ≡ 0 (mod 3): `J(n) = T_{(2n−3)/3}`
  - n ≡ 1 (mod 3): `J(n) = 2(n−1)/3`. 3 | N이면 교환 위치가 N/3 주기로 돌아오기 때문입니다.
- 즉 C1 기울기가 g ≈ 4n²/9까지 유지됩니다.

**n = 7에서의 일치.** special-c₇ walk의 정확한 최대(DFS, `walk180.py`)는 charge 2..16에서 9, 13, 16, 20, 24, 27, 31, 34입니다. 외부 Lean 인증표 `capTab`과 **완전히 같습니다.** 따라서 이 walk들이 그 범위의 capacity 극대자입니다.

## 4. 2영역 정리와 문턱값

- **낮은 charge (g ≤ 2K):** C1이 증명된 상한이고, 정리 W에 의해 덧셈 오차 n−3 안에서 정확합니다. 이것이 낮은 charge의 완결된 처리입니다.
- **큰 charge:** LS₍≥g₀₎(A = O(n), c = O(1))가 성립하려면 **g₀ > 2K = 2⌊(n−3)/3⌋ (증명)**, 경험적으로는 g₀ > 2J(n) ≈ 4n²/9입니다.
- 그런 LS가 **실제로 성립하는 문턱값은 확립하지 못했습니다.** 하한이 결정되는 영역은 단일 trail에서 g ≈ 2(n−2)!/n인데, walk는 그 영역에 닿지 않습니다.
- 두 영역의 연결: g < g₀에서 `C1(g) ≤ A′ + c·g`, A′는 §1의 식. 연결은 산술이므로 자명합니다.

## 5. payload 없는 극단점 (r = a = b = η = 0, m = D)

이때 τ = 1, row 수 k = (n−2)! + m, charge = (n−1)m이고, 모든 순환류를 **정확히 분할**해야 합니다(R179 명제 E).

| 질문 | 상태 |
|---|---|
| (a) marked-row relaxation (`CoarsenedInstance`)에서 실현 가능? | n = 6은 D ≤ 4에서, n = 7은 D ≤ 13에서 **불가능**(외부 Lean의 capacity 소거가 r = 0 경우도 포함). **n ≥ 8은 미해결.** 필요한 row 수 ≈ (n−2)!는 walk들(≈ 2n³/9)보다 훨씬 큼 |
| (b) ForestInstance 조건과 양립? | b = 0이므로 (iii)이 강제되고, payload 없음, charge = u, 정확 분할. 추가 제약은 정확 분할뿐입니다. **미해결** |
| (c) 실제 route로 실현? | r = 0이면 모든 순환류가 run 하나로 통째 지나가야 합니다. 알려진 최적 route는 r > 0입니다(예: n = 6의 872 route는 r = 18, m = 4). **미해결** |
| (d) 추가 구조 불변량으로 배제? | 일반 n에서 증명된 것은 **없습니다** |

payload 의무가 없다는 사실에서 실현 가능성을 추론하지 않았습니다. 네 질문은 서로 다릅니다.

## 6. Δ(n)에 대한 올바른 함의

**(1) R178 (C1 = LS(n; n−2, (n−3)/2)).** n ≥ 6에서 `Δ(n) ≥ ⌈2(n−2)((n−3)!−1)/(n²−4n+1)⌉`. 이것이 **여전히 가장 강한 정당화된 하한**입니다(비형식 종이 증명).

**(2) 2영역 LS₍≥g₀₎(A, c)가 참이라면.**
- `ls_core`를 A′로 적용하면 `Δ(n) ≥ ⌈((n−2)! − A′)/max(A′, c(n−1)−1)⌉`입니다.
- 정리 W에 의해 A′ ≥ (n−2) + ((n−3)/2 − c)·2K ≈ n²/3입니다. 따라서 이 하한은 많아야 ≈ 3(n−2)!/n², 즉 R178의 약 1.5배입니다.
- 경험적 문턱 g₀ ≈ 4n²/9에서는 A′ ≈ 2n³/9가 되어 R178보다 **약해집니다.**
- 정수 올림, 분모의 양수성(A′ ≥ 1, c(n−1) − 1 ≥ 1), 삼분법 세 경우 모두 `ls_core`의 가정(trail별 상한의 합)과 일치합니다. 세 경우 모두 같은 trail 합 부등식을 쓰기 때문입니다.

**(3) 천장 정리 (trail별 capacity 논법의 한계).**
- trail별 capacity 논법이란 "Bridge 인스턴스가 있으면 `k ≤ Σᵢ M_n(cᵢ)`"만으로 D를 아래로 묶는 논법입니다.
- 정리 W의 `M_n(2K) ≥ (n−3)K + 1`을 쓰면 다음 매개변수에서 그 부등식이 **만족**됩니다.
  - r = a = b = 0
  - 각 trail charge 2K, trail τ개
  - `m = ⌈2Kτ/(n−1)⌉`, `τ((n−3)K + 1) ≥ (n−2)! + m`
- 따라서 이 논법으로는 `D_ceil = min_τ (m + τ − 1)`보다 큰 하한을 증명할 수 없습니다.
- 수치 (`certs/ceiling180.txt`):
  - 증명된 입력: R178의 2.6–3.7배 (n ≤ 40), 점근적으로 **2.5배**(효율 n²/5 대 n²/2).
  - 경험적 walk 입력: 1.06–1.39배 (n ≢ 1 mod 3), 1로 수렴.
- **결론:**
  - LS를 포함한 어떤 trail별 capacity 개선도 하한을 **Θ((n−3)!/n) 차수 밖으로 옮길 수 없습니다**(증명).
  - R179 따름정리("A = O(n), c = O(1)이면 Θ((n−3)!)")의 가정은 거짓입니다(정리 W).
  - 이 천장은 **증명 방법**에 대한 것입니다. 이 매개변수에서 실제 인스턴스(trail들 사이의 전역 서로소 포함)가 존재한다는 뜻은 **아닙니다.**

## 7. B2 형식화

`r180/lean/B2Route.lean`은 core Lean 4.22.0에서 컴파일되며 `sorry`가 없습니다.

| 정리 | 내용 | 공리 |
|---|---|---|
| `runStart_rot_iff` | R가 단사이고 R e가 route에 있으면: **R e가 run start ⇔ route가 e → R e로 가지 않음** | 없음 |

| `run_end_next_is_start` | run이 R^k s에서 멈추면 R^{k+1} s는 run start. 따라서 A(s) = R^{k+1}s, run 끝 = R^{−1}A(s) | 없음 |

- 이것은 B2의 **실제 route 이론적 내용**(유일한 cost-1 선행자, run의 내부와 끝)입니다.
- **아직 형식화하지 않은 것:**
  - run 길이 k의 존재(유한성과 route의 무중복)
  - "모든 순환류가 S와 만난다"(route는 경로이므로 순환류의 R-간선 n개를 모두 쓸 수 없음)
  - B6, B8의 trail 구조, B9–B11의 집합 계수
- 네 Lean 파일(R178 `BridgeCore`, R179 `BridgeGeom`, `LSReduction`, R180 `B2Route`)의 16개 정리는 모두 오류와 `sorryAx` 없이 컴파일됩니다(`certs/lean_all_180.txt`).

## 8. 정확한 보편 공식까지의 장애물

1. **capacity relaxation 자체의 한계가 확정되었습니다.**
   - 단일 trail capacity는 적어도 g ≈ n/3까지(증명), 경험적으로 g ≈ 4n²/9까지 C1 기울기 (n−3)/2를 유지합니다.
   - 천장 정리에 의해 trail별 논법은 하한을 Θ((n−3)!/n)보다 높일 수 없습니다.
   - Egan 상계 (n−3)!와의 **n배 간격을 닫으려면 trail들 사이의 전역 제약**이 필요합니다: 서로 다른 trail의 서로소 packing, 정확 분할, payload, route 실현 가능성.
2. **다음 구체적 질문 (P-global):** 모든 순환 단어(또는 순환류)를 trail당 charge 약 n²인 walk들로 서로소 packing할 때 필요한 D가 R178 하한 수준(≈ 2(n−3)!/n)인가, 아니면 (n−3)! 수준인가?
